# ADR-012 · M2 身份、资源与当前授权边界

状态：已接受实施，2026-10-03。依据为所有者 M2 开工授权、M2-01 至 M2-13 和 ADR-006/007/008/011。M1 人工核验与收口确认仍待完成。

## 资源关联与历史保留

组织包含工作区和成员资格，成员资格关联用户与 owner/admin/member 角色。工作区成员表记录该成员可访问的工作区；owner 可访问本组织全部工作区，admin 仅管理已登记工作区，member 仅使用登记工作区内具有 user→agent Grant 的员工。员工为长期保存的 Agent 资源，保存岗位、main/aux 模型槽、Skill 和连接器引用、修订及状态。资源引用校验同组织和同工作区；引用列表本身不授予能力。

Skill 与 M1 的 store_id 使用同一稳定身份。每次正文或支撑材料变更通过 M1 持久化意图服务生成一个 skill_versions 记录，change_id 唯一关联账本与版本。版本保存正文、metadata、支撑文件及 SHA，SQLite 触发器禁止修改和删除历史版本。恢复旧正文同样追加版本。员工对 Skill 和连接器的有效 Grant 使用部分唯一索引；撤销保留历史，重新授予创建新记录。

删除资源采用 disabled/archived 状态，保留历史身份、修订、文件和关联记录。工作区目录由服务分配，API 不接受客户端将任意系统目录指定为数据目录。旧 default 工作区、员工、owner、规则及三库身份明确映射为组织资源，未知身份必须逐条验证来源后登记；无法证明归属时升级失败并进入诊断，不能自动授予能力。迁移不改写历史事件或审计内容，升级前使用 VACUUM INTO 保存自洽备份。

## 请求身份与访问控制

本地随机 Bearer 始终绑定真实 owner。POST /api/identity/demo 通过该凭证认证并检查组织成员，返回服务端生成的不可猜测 identity_token。请求可通过 X-AgentCrew-Identity 携带该标识；服务端读取持久化标识绑定的 effective_user_id，并检查当前成员状态及角色。未提供标识时使用真实 owner。客户端 actor/role 字段不作为身份来源，未知或失效标识返回401。每个请求建立不可变身份对象，任务、审批、排队和后台作业保存该对象的真实及有效用户标识，执行时另行读取当前权限。

切换身份只影响使用返回标识的窗口。SSE 在每次补播、实时发送和心跳时复查当前可见性；成员资格、工作区访问或员工 Grant 撤销后结束无权订阅，客户端清理旧身份的正文、草稿以外缓存与游标并重新查询。成员仅访问本人会话、运行、材料、产物和后台记录；admin 管理资源不自动获得其他成员私有会话。owner 可核查本组织记录。旧接口同样使用这些边界。

| 操作 | owner | admin | member |
|---|---|---|---|
| 当前身份、本人可见工作区和员工、本人会话及运行 | 本组织范围 | 登记范围及本人会话 | 登记范围、员工 Grant 及本人会话 |
| 成员查询、组织及角色修改、工作区成员变更 | 允许，禁止撤销最后有效 owner | 仅查询自身成员身份 | 仅查询自身成员身份 |
| 工作区、员工、Skill、连接器、Grant、规则管理 | 允许 | 所属登记工作区 | 拒绝403 |
| 本人任务审批、停止、队列、核验和恢复 | 当前授权有效时允许 | 当前授权有效时允许 | 当前授权有效时允许；永久规则决定拒绝403 |
| 审计查询及脱敏导出 | 本组织 | 所属工作区 | 自身 actor 记录 |

## 强制范围与连接器

执行先规范化读写 scope 和 protected 路径，再核查当前角色、员工可见性、资源状态及 Grant，然后检查 deny、风险元数据、allow 和人工审批。deny 对只读操作也优先。bash 规则仅匹配完整命令，追加命令不会命中；所有 bash 网络由 Seatbelt 禁止。外部目录经用户明确加入 scope 后可以审批，scope 外直接拒绝。人工审批不能改变 scope、protected、角色、Grant、连接器主机与端口限制。

连接器 HTTP 配置声明目标 URL、allowed_hosts、allowed_ports、allow_loopback、管理员批准的风险及幂等端点。主机规范化使用 IDNA，URL 禁止 userinfo、fragment 和非 HTTP(S) 协议；DNS 结果必须符合地址策略，禁止通过重新解析访问未批准地址。重定向每一跳独立校验且跨来源不转发凭据。默认拒绝本地、链路本地与私有地址，独立验收服务通过明确 allow_loopback 和精确主机/端口允许。凭据由服务端绑定于连接器和来源，API 只展示 configured 状态；模型不能传入或覆盖认证头、Cookie、Host、代理及幂等头。

MCP 使用成熟 SDK，支持 stdio 与 streamable_http。网络传输共享目标限制；stdio 启动仅使用固定环境白名单，加载同源 scope/protected 的 Seatbelt profile，网络全禁，子进程关闭并收割后才完成调用。工具名称使用 mcp_<connector_id>_<tool_name> 稳定身份且不得覆盖内置工具。风险元数据由管理员批准，未声明时需要审批且副作用为 outcome_unknown。连接失败明确返回错误，不以空工具数组表达成功。

## 快照、撤销与恢复

会话三库继续冻结。每个任务另行绑定员工配置和 Skill 版本；恢复沿用原任务版本、三库快照、压缩检查点和账本。新任务读取最新员工配置与版本。有效 Skill 索引及正文使用任务版本和当前 Grant 的交集，每次模型请求重新生成有效工具声明并保存授权指纹。

授权检查与 tool.dispatched 事件及投影登记在同一写通道事务完成。撤销事务先提交时，后续派发失败；调用先登记派发时，撤销提交后取消实际执行、关闭流与子进程并核对真实效果。取消不抹去已发生副作用。未知效果或内容 SHA 不一致进入 pending_verification，在核验结束前禁止后续派发和恢复。外部幂等键仅适用于真实上游承诺去重的端点，同次调用保持稳定键，新 call_id 使用新键。

审批绑定 task/attempt/call_id/input_hash/agent/resource。提交时检查活动执行方和当前角色、资源、Grant 与规则，失去执行方的未决定审批返回409 APPROVAL_STALE，不能新增规则；已有决定相同重试保持幂等。member 永久决定无权写入规则。后台作业和员工工具面不包含治理写入，通用文件工具和子进程禁止访问治理数据库、配置、凭据及持久化提示词载体。

## 治理事务、审计与诊断

治理业务、审计和范围事件同事务，提交后按串行提交顺序发布。治理事件使用 org_id/workspace_id/agent_id/owner_id 可见范围，没有会话关联时不创建 task_run_id/seq。分页游标绑定有效身份、过滤和范围，limit 上限200，陈旧修订返回409 REVISION_CONFLICT，复用 change_id 的不同内容返回409 IDEMPOTENCY_CONFLICT。

审计验证分别报告内部全量重算和 chain-head.txt 的 seq/hash/覆盖范围；锚点缺失、格式损坏和不匹配均明确失败。正常退出及每100条追加维护锚点，已损坏链禁止追加验证结果或覆盖锚点。两级验证失败后进入只读诊断，停止任务及后台作业，保留认证后的诊断查询、导出和验证。诊断恢复仅接受服务登记并核验的备份标识，不接受任意文件路径；保留损坏数据库及锚点，恢复后必须重启和完整验证。数据库备份恢复仅恢复数据库；整目录灾备还必须恢复 Skill/Memory/工件和锚点。数据目录外的 chain-head.txt 副本提供独立锚点，拥有整个数据目录写权限者仍可同时改写库与本地锚点。

M2 API 操作及实施归属见 [操作矩阵](../contracts/m2-operations.md)，事件载荷见 [事件契约](../contracts/events.md)。真实 HTTP 核查在 M2-03/M2-11 与各领域卡完成，七项治理、额外安全、M0/M1 回归在 M2-13 逐项计分。
