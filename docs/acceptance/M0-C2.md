- **版本化迁移**（`db/migrations.py`）：目标>当前 → `VACUUM INTO backups/db-v<旧>-<时间戳>.sqlite` 升级前快照（保留 3 份）→ 每条迁移单独事务；目标<当前 → 拒绝启动报双版本号；中途失败 → 该事务回滚 + 只读诊断模式
- **写通道**（`db/write_channel.py`）：单写 executor（单线程线程池）+ busy/locked 退避重试 3 次；读走独立只读连接（`query_only=ON`，WAL 并发读）
- **EventStore**（`db/event_store.py`）：事件追加 + 投影同事务（事务内 `defer_foreign_keys`——RUN_QUEUED 的 task_runs 父行由本事务投影创建）；任务内 seq = max+1，UNIQUE(task_run_id,seq) 兜底抛错不覆盖；提交成功后 publisher 回调（C3 注入总线），发布顺序 = 提交顺序
- **投影处理器 + 重放器**（`db/projections.py`）：M0 全部 29 种事件类型注册（run.*/step.*/llm.*/tool.*/artifact.*/materials/conversation 有投影；permission/question/queue/context 显式 no-op，等 C7 reducer）；`rebuild_projections` 擦除投影表按 global_seq 重放，结果与在线写入逐行一致
- **审计链**（`db/audit.py`）：`compute_hash` canonical 串（sha256，governance §3 公式）；两级校验（内部全量重算含 seq 连续性 + chain-head.txt 锚点比对）；正常退出链头原子快照；C2 起 cli 启动即真实校验（空链通过，C6 起有写入方）
- **只读诊断模式**：迁移失败/审计链断 → 业务端点 503 `DIAGNOSTIC_MODE`，仅 `/api/health` 与 `/api/diagnostics`（reason + 从 backups/ 还原提示）可用；契约新增 `/api/diagnostics`（openapi v0.3，守卫通过 29 paths）
- agentcrew_core 填充：`RunEventType` 枚举 + `Event` 信封（`as_frame()` 与 SSE 帧形状一致）+ `EventStore` Port

## 6. 与设计的偏差及决策说明

1. **事务内 `PRAGMA defer_foreign_keys=ON`**（实现层决策）：`run_events.task_run_id` 有 FK 指向 `task_runs`，而 task_runs 行恰由 RUN_QUEUED 的投影在同一事务内创建——"事件先插、父行后建"在立即检查的 FK 下必然失败。延迟到 COMMIT 检查后语义不变（坏引用仍在提交处如实失败并整体回滚，§3 验收证明）。
2. **task_runs 的 waiting_user / waiting_verification 投影暂缓**：这两个派生态依赖 C7/C8 reducer 的状态互斥规则（提问/审批/核验与 running 的关系），C2 只实现 run.* 直接迁移，避免预发明 C7 的语义。重放一致性不受影响。
3. **审计链 C2 只交付校验与退出快照**（卡原文"建好备用"）：写入方（哈希链追加、每 100 条快照）随 C6 审批决定落地，复用本卡 `compute_hash` 保证链式一致。
4. **契约新增 `/api/diagnostics`**：backend-service §1 原文只说"诊断端点"未定名，C2 落为 `/api/diagnostics` 并入 openapi v0.3（`check_openapi.py` 通过：29 paths）；文档 §1 已同步（v1.3）。
5. 环境注记：守卫脚本需 PyYAML，系统 python3 未装，实际以 `uv run --no-project --with pyyaml python scripts/check_openapi.py` 执行通过。
