## 触发、输入与工具

SQLite v9 持久化用户回合、工具迭代、逐事件去重记录和触发水位。直发指令按 `run.queued` 计数，排队按 `queue.item_enqueued` 计数，出队和恢复尝试保持已有计数；含非空 `tool_uses` 的一个 `llm.request_done` 只计一次工具迭代。每十个用户回合创建记忆提炼，每十五次工具迭代创建 Skill 审查；各作业引用对应阈值的真实事件水位，在任务交付且系统空闲后开始。重复事件、恢复和同一触发键保持首次结果。

后台输入包含近期二十四条原始消息、具有更早消息的任务完成摘要和缺失摘要任务标识。长任务跨越二十四条边界时仍保留该任务的摘要与目标。文本、思考内容、历史工具参数及嵌套字段执行投毒过滤，模型上下文使用 BLOCKED，持久化原始事件保持完整。当前范围的 Skill 索引包含描述和修订，正文通过受控读取按需披露，索引读取不计为正文使用。

每次 aux 请求使用正式 tokenizer 核查完整 system、四个工具声明、资料、索引、历史、工具结果及输出预算，完整输入上限为窗口 75%，同时保持 M1-07 的区域预算。后台注册表只包含 `memory_write`、`skill_patch`、`session_search`、受任务范围限制的 `read_file`。三库及 Skill 复用已有文件一致性协议、来源与依据、修订校验、高风险审核、配额和三次失败上限。后台来源携带真实 `job_id`，作业停止后禁止继续读写。

## 独立审批与取消

可选写入审批通过真实 Settings GET/PATCH 配置，绑定作业的配置快照。后台工具按调用顺序完成 prepared、独立审批和执行，审批绑定 `job_id/call_id/input_hash`，只允许本次允许或拒绝。审批请求、决定、作业状态和审计同事务提交，通过会话后台事件展示，不增加前台等待计数。重复同决定读取首次结果，参数变化、不同决定和已失效审批返回 409。取消及启动恢复使旧审批失效。
