# M0 C10 · Electron 壳与 sidecar 监管验收

验收日期：2026-09-30。分支：`desktop-shell`；基线：`cc442f8`；后端基线：`main` 的 `f3ac448`。本记录、桌面代码和截图属于同一次 C10 提交。运行环境为 macOS，`desktop/` 使用 npm，后端由 `uv run python -m agentcrew_server` 启动。

## 实现与检查

main 进程为每次 sidecar 启动生成随机 token，经 `AGENTCREW_TOKEN` 环境变量传入真实后端；stdout 解析 `AGENTCREW_READY {"port":N}`，以实际端口完成 `/api/health` 信封检查。启动期其他输出经过机密过滤后留存。启动 30 秒超时、异常标记和子进程退出均触发清理；60 秒内最多重启三次，退避为 1、2、4 秒，超限弹窗提供启动失败原因及 `sidecar-launch.log` 路径。preload 仅暴露 `getBackendPort/getToken/notify/openPath/setKeepAwake`，窗口启用 context isolation 与 sandbox。渲染层健康请求携带 `Authorization: Bearer`，断开后持续检查并在恢复后显示已连接。托盘保留后端、重新打开窗口和显式退出；退出前显示任务中断警告。主进程传入自身 PID 供后端看护。

执行 `cd desktop && npm run build`，TypeScript 类型检查通过，main、preload、renderer 构建成功。`git diff --check` 通过。后端日志中未检出连续 64 位十六进制 token。没有调用任务创建等尚未交付的 C7 业务端点。

## 真机验收

在 `desktop/` 执行 `npm run dev`，Electron 窗口和真实 Python 后端由一条命令启动。进程输出显示 `Electron[32067]`，`ps` 显示 `uv` 的父进程为 `32067`，Python 启动参数为 `--parent-pid 32067`。后端在 `127.0.0.1:56560` 就绪，`curl http://127.0.0.1:56560/api/health` 返回 `{"data":{"status":"ok"}}`；窗口辅助功能树显示“任务服务已连接”。截图：[启动连接](assets/C10/connected.jpg)。

执行 `kill -9 32097` 真正终止 Python sidecar。监管随后启动新的 Python 进程 `32280`，实际端口变为 `57507`；日志出现 `http.ready listening on 127.0.0.1:57507`，新端口健康检查仍返回 `{"data":{"status":"ok"}}`。窗口恢复后的截图：[重新连接](assets/C10/reconnected.jpg)。持续终止后端四次后，前三次得到新进程，第四次没有继续重启；真实弹窗显示“已达到自动重启上限”及应用数据目录下的 `logs/sidecar.log` 路径。关闭弹窗后窗口辅助功能树显示“任务服务正在重新连接”。截图：[重启超限](assets/C10/restart-limit.jpg)。

点击窗口关闭按钮后，`ps` 仍显示 Electron `32067` 与 Python `32280`，`lsof` 仍显示后端监听 `127.0.0.1:57507`；菜单栏截图：[关窗驻留](assets/C10/tray-resident.jpg)。在 `desktop/` 再执行 `./node_modules/.bin/electron .`，第二个实例立即退出，原 Electron PID 保持 `32067`，原窗口重新显示；截图：[单实例](assets/C10/second-instance.jpg)。

从应用显式退出菜单打开警告，辅助功能树显示“退出后任务服务会停止。如果有正在运行或等待审批的任务，退出会中断处理。”及“取消”“退出”按钮；取消后窗口和后端继续运行。再次确认退出后，`ps` 找不到 Electron 或 `agentcrew_server` 进程；后端日志包含 `shutdown.done` 与 `shutdown.exit 正常退出（exit 0）`。截图：[退出警告](assets/C10/exit-warning.jpg)。另外，用构建产物启动 Electron `34233`，确认 Python 参数 `--parent-pid 34233` 后执行 `kill -9 34233`；日志出现 `shutdown.begin 触发源=parent-exit`，四秒后 `ps` 未发现残留后端进程。

## 设计偏差

C10 原卡写 `pnpm dev`；既有 FE00 工程使用 npm 与 `package-lock.json`，因此交付命令为 `npm run dev`，具备同样的一键启动能力。C7 的任务状态接口尚未交付，当前显式退出统一提示运行中或等待审批任务可能中断，不展示未经后端确认的任务数量；真实影响清单留在依赖 C8/C9 的 FE09 后续范围。

### 启动超时与退出清理

核实基线在 Python 收到 `SIGSTOP` 后，仅发送 `SIGTERM` 无法确保退出：原 uv/Python PID `41802/41803` 在六秒后仍然存在，Python 状态为 `T`。实现改为使用独立进程组监管真实 uv 与 Python，先向整组发送 `SIGTERM`，五秒后仍未退出则向整组发送 `SIGKILL`；收到 `close` 后才进入重试。应用退出同样等待清理，强制终止后最多再等待两秒确认，确认失败则提示并保持应用运行。

可重复执行的真实检查为 `cd desktop && node tests/c10-startup-stop.mjs`。脚本启动构建后的 Electron，在 Python 输出就绪标记之前对 Python 与 uv 发送真实 `SIGSTOP`，确认 `T` 状态和尚未就绪，随后验证 30 秒启动超时、五秒清理期限、替换进程出现、旧进程消失。脚本还暂停替换后的 uv/Python，触发应用退出并核对清理耗时与孤儿进程。[实际进程与计时输出](assets/C10/review-stop-output.txt)随本次提交保存。

另外，通过原生退出菜单完成暂停 Python 的人工界面路径：Electron `59305`、uv `59430`、Python `59431`，Python 状态为 `T`；`09:42:15.998Z` 点击“退出”，`09:42:30Z` 的 `ps` 查询三个 PID 均为空。[原生对话框与 ps 输出](assets/C10/review-dialog-ax.txt)记录实际观察；[暂停后的前端连接状态](assets/C10/review-stopped-connection.png)显示“任务服务正在重新连接”。

### 启动故障原因

核实基线丢弃 stdout 非就绪内容并排空 stderr。现在按完整行过滤当前 token、环境中的机密值及 Bearer/API key 形式，再保留最近 4096 个字符；超过上限的 stderr 单行整体省略。失败时将过滤后的输出写入应用数据根目录下的 `sidecar-launch.log`，新建文件权限为 `0600`，避免不可写的后端 `data/` 目录阻断启动日志。原生超限弹窗显示实际失败原因及该日志位置。

真实验收对 `.artifacts/c10-dialog/data` 设置 `0500` 权限并在四次启动期间保持该权限；Electron PID `58328`。后端分别在 `09:38:43.724Z`、`09:38:44.984Z`、`09:38:47.230Z`、`09:38:51.511Z` 返回退出码 1，stderr 均为 `启动失败：data-dir 不可写：…/data（Permission denied）`。原生弹窗辅助功能文本确认同时显示“已达到自动重启上限”、上述原因及真实日志位置，见[弹窗输出](assets/C10/review-dialog-ax.txt)和[启动日志](assets/C10/review-permission.log)。[故障时的窗口截图](assets/C10/review-permission-state.png)保留主窗口连接状态；弹窗内容以原生辅助功能输出为证。验收后恢复测试目录权限。
