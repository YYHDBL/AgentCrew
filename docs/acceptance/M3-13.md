## 页面实现

新增自动化页面，接入现有 cron HTTP 与事件接口。用户可以按正式契约创建、修改、启停、删除和手动运行计划，查看 `at`、`every`、`cron` 参数、IANA 时区、员工、会话模式、指令、服务端授权预览、下一次运行、创建身份和发生历史。编辑范围和角色检查失败时保留表单内容并展示实际服务端错误。现有会话选择只显示当前身份可见的会话。

员工 `schedule_task` 卡片读取持久提案，展示原始参数、`input_hash`、来源 TaskRun、员工和服务端候选范围。范围勾选保存在单独的决定请求中；页面只提交契约允许的 `allow_once` 与 `reject_once`。普通计划事件刷新列表时保留待审批提案；requested/resolved 事件均读取持久状态，按修订号合并，较早返回的数据不能覆盖较新决定。刷新与重连从持久事件重新读取当前状态。身份、工作区、员工或只读诊断范围变化时清理已加载内容；异步请求在范围代数变化后不再更新页面。

已有计划的员工身份固定，编辑表单禁用员工选择；新建计划按所选员工显示可见会话。服务端预览与保存期间禁用表单字段及范围勾选，避免请求返回后覆盖用户后续输入。保存、预览的结果与错误均检查当前范围代数。

发生记录展示 `missed`、`skipped`、`failed`、`interrupted`、`pending_verification`、`retry_wait`、`completed` 和 `cancelled`，保留 occurrence、retry_no、attempt_no 与 TaskRun 关联。TaskRun、报告与产物打开 Run Center；中断和待核验记录提供返回工作台现有安全处理流程的入口。页面没有自动恢复、审批重提或暂停队列继续操作。审批弹窗初始焦点进入计划名称输入框，按 Escape 关闭后焦点返回“新建计划”。

## 真实 Electron 验收

验收使用 Electron、真实 sidecar HTTP、SQLite、文件、子进程和当前配置的真实模型。实际配置为 `main=deepseek-v4.1-flash`、`aux=deepseek-v4.1-flash`，provider 为 `openai-compatible`，请求地址为 `https://opencode.ai/zen/go/v1`。没有改写模型配置或制作模型响应。

本轮真实页面流程创建了三种计划。`at` 计划到期后产生唯一 scheduled occurrence、completed TaskRun 和真实文件；`every` 计划到期后形成 scheduled occurrence，与执行中 TaskRun 冲突的手动发生记录为 skipped。界面停用该计划后，尚未通过首次工具派发检查的 TaskRun 以 `PLAN_DISABLED` 结束，未产生文件，后续 occurrence 停止。`cron` 计划通过页面创建后手动触发，实际生成文件，再通过页面修改表达式、停用和删除；历史仍保留。另有一项页面创建的 `existing` 计划被编辑为 `new_conversation`，服务端保存了会话模式与目标变化。

通过真实 `SIGSTOP/SIGCONT` 越过一次性计划时刻，后端 SQL 和页面均显示 `missed`，没有生成 TaskRun。另一个无人值守写入在未选择计划预授权时返回 `PRE_AUTH_EXCEEDED`，保存拒绝事件，目标文件没有生成。

页面通过真实模型任务取得不可变 `schedule_task` 提案。批准前 SQL 中该提案对应零个计划，页面选择服务端候选目录并批准后只存在一个计划；同一决定重放仍返回同一个计划。获批计划真实写入并读取文件。另一个模型提案从页面被拒绝，服务端没有创建计划；第三个待审批 TaskRun 经真实取消后，提案进入 `expired`，页面移除待审批卡并显示失效记录，旧决定返回 409，计划数仍为零。真实 `member` 身份 `lilei` 的批准请求返回 403。切换到 `lilei` 后页面清除了 owner 的计划与提案，回到 owner 后重新读取。宽屏、审批卡、窄屏截图和焦点操作证据见 [assets/M3/13](assets/M3/13/)。

通过真实 HTTP 服务将 POST 正文持久化到独立 SQLite，在响应返回前对 sidecar 执行 `SIGKILL`。真实 Electron 监管重启后，TaskRun `df9ca9c294b04c3c9e701836fd71cb9a` 保持 `waiting_verification`，occurrence `d519e1d924f4400d9b99eb1ef2b8532c` 为 `pending_verification`，自动重试次数为 0、retry_at 为空。恢复请求返回 409。页面显示待核验历史并进入同一任务的工作台核验区域；上游仍只有一次操作，SHA256 与 mtime 保持不变。计划为 `bc71fe4c24cd5988a1887fb755826071`，完整请求、Grant、规则、信号与文件证据见 [专项 JSON](assets/M3/13/automation-electron-reviewed.json)。
