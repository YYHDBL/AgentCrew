## 页面实现

新增自动化页面，接入现有 cron HTTP 与事件接口。用户可以按正式契约创建、修改、启停、删除和手动运行计划，查看 `at`、`every`、`cron` 参数、IANA 时区、员工、会话模式、指令、服务端授权预览、下一次运行、创建身份和发生历史。编辑范围和角色检查失败时保留表单内容并展示实际服务端错误。现有会话选择只显示当前身份可见的会话。

员工 `schedule_task` 卡片读取持久提案，展示原始参数、`input_hash`、来源 TaskRun、员工和服务端候选范围。范围勾选保存在单独的决定请求中；页面只提交契约允许的 `allow_once` 与 `reject_once`，不会把 `allow_always` 当作创建批准。刷新会重放持久提案事件并重新读取当前状态。身份、工作区、员工或只读诊断范围变化时清理已加载内容；异步请求在范围代数变化后不再更新页面。

发生记录展示 `missed`、`skipped`、`failed`、`interrupted`、`pending_verification`、`retry_wait`、`completed` 和 `cancelled`，保留 occurrence、retry_no、attempt_no 与 TaskRun 关联。TaskRun、报告与产物打开 Run Center；中断和待核验记录提供返回工作台现有安全处理流程的入口。页面没有自动恢复、审批重提或暂停队列继续操作。审批弹窗初始焦点进入计划名称输入框，按 Escape 关闭后焦点返回“新建计划”。

## 真实 Electron 验收

验收使用 Electron、真实 sidecar HTTP、SQLite、文件、子进程和当前配置的真实模型。实际配置为 `main=deepseek-v4.1-flash`、`aux=deepseek-v4.1-flash`，provider 为 `openai-compatible`，请求地址为 `https://opencode.ai/zen/go/v1`。没有改写模型配置或制作模型响应。

本轮真实页面流程创建了三种计划。`at` 计划到期后产生唯一 scheduled occurrence、completed TaskRun 和真实文件；`every` 计划到期后形成 scheduled occurrence，与执行中 TaskRun 冲突的手动发生记录为 skipped。界面停用该计划后，尚未通过首次工具派发检查的 TaskRun 以 `PLAN_DISABLED` 结束，未产生文件，后续 occurrence 停止。`cron` 计划通过页面创建后手动触发，实际生成文件，再通过页面修改表达式、停用和删除；历史仍保留。另有一项页面创建的 `existing` 计划被编辑为 `new_conversation`，服务端保存了会话模式与目标变化。

通过真实 `SIGSTOP/SIGCONT` 越过一次性计划时刻，后端 SQL 和页面均显示 `missed`，没有生成 TaskRun。另一个无人值守写入在未选择计划预授权时返回 `PRE_AUTH_EXCEEDED`，保存拒绝事件，目标文件没有生成。

页面通过真实模型任务取得不可变 `schedule_task` 提案。批准前 SQL 中该提案对应零个计划，页面选择服务端候选目录并批准后只存在一个计划；同一决定重放仍返回同一个计划。获批计划真实写入并读取文件。另一个模型提案从页面被拒绝，服务端没有创建计划；第三个待审批 TaskRun 经真实取消后，提案进入 `expired`，旧决定返回 409，计划数仍为零。真实 `member` 身份 `lilei` 的批准请求返回 403。切换到 `lilei` 后页面清除了 owner 的计划与提案，回到 owner 后重新读取。宽屏、审批卡、窄屏截图和焦点操作证据见 [assets/M3/13](assets/M3/13/)。

执行证据包含 **3,642** 条真实 HTTP 请求和响应、**79** 条完整 SQL 查询、查询结果、**240** 条事件序号、**5** 个 TaskRun、**5** 条执行 attempt、**7** 条 occurrence、**2** 份员工提案和 **32** 条关联审计查询记录。所有发生与任务关联、文件 SHA256、完整路径和 mtime、参数哈希、批准选择、审计序号及哈希均保留完整值。审计内部重算核验 **93** 条记录通过，独立 chain-head 校验通过，链头为 seq `10`、hash `fe1a3738f405f2309ad3c3ff0d84072e7c2d118d1c55deba50609285f5dc565f`。公开证据中的当前配置密钥匹配数为 **0**。
