## 0. 交付物清单

- **闸门判定纯函数**（`agentcrew_core/tools/gate.py`）：
  - `evaluate_gate`：三级判定——① 元数据分级（只读含 bash 动态只读放行；risk=high × destructive 硬拒；needs_approval 进 ②）→ ② 员工规则表（deny > allow；按 agent_id + tool_name 过滤）→ ③ ask
  - `rule_matches`：pattern 语义——write_file 路径前缀（realpath 规范化）、bash 命令前缀、http_request 域名（含 `*.suffix` 通配）
  - `always_scope_pattern` / `approval_target`：allow_always 落规则的 pattern（write_file→目标目录、bash→命令首词、http→域名）= 审批卡上的 always_scope_preview（G1"工具+资源范围"）
- **调度器 gate 挂钩**（scheduler）：事件序列 §6.2——prepared 落库 → 闸门（ask 在此挂起）→ dispatched → 执行；deny 补记 tool.failed(PERMISSION_DENIED)
- **审批服务**（`agentcrew_server/approvals.py`）：
  - PERMISSION_REQUESTED（四选项/input_hash/target/always_scope_preview）→ 挂起 asyncio.Future → 决定 → PERMISSION_RESOLVED → 唤醒
  - 决定语义：同决定重试 200 幂等回首次结果；不同决定 409 APPROVAL_STALE；携带 input_hash 不一致 409；无 REQUESTED 404
  - allow_always / reject_always 按 always_scope_preview 写 `agent_permission_rules`（挂员工名下、可回收）
  - 每次请求与决定写 `audit_log` 哈希链（C2 建表 C6 首次写入）；每 100 条快照 chain-head.txt
  - 重启恢复：pending 卡从事件流查询（REQUESTED 无 RESOLVED），无 Future 仍可提交决定并落库
  - 跨线程唤醒：HTTP 服务线程的决定经 `call_soon_threadsafe` 唤醒执行循环的 Future（实测修复的竞态）
- **API**：`POST /api/tool-approvals/:callId`（body 含可选 input_hash）+ `GET /api/task-runs/:id/approvals?status=`（契约 v0.3；openapi 补 input_hash 可选字段，守卫 29 paths 通过）
- **装配**（cli）：EventStore → ApprovalService → ToolScheduler(gate) → runtime

## 3. 与设计的偏差及决策说明

1. **闸门拿不到 WorkContext**：调度器挂钩签名无 ctx（闸门在 run_tool 注册表里按 call_id 查执行上下文）——ask 需要的 task/conversation/agent 信息在 run_tool 入口已注册；重启后的孤儿卡查不到上下文时报 ApprovalNotFound（执行早已随进程消亡，属 C9 对账域）。
2. **decided_at 以库内落库时刻为准**：幂等重放与首次返回微秒级一致（Python 时钟与 SQLite 写入时刻本有微差，统一读库）。
3. **审计链快照时机**：每 100 条由 `_audit` 在追加后触发（demo 量小走不到，退出快照由 C2 的 shutdown 钩子兜底）；链一致性由 verify_with_anchor 全量重算保证。
4. **未做项（按卡归属）**：审批期间用户取消任务（释放挂起）——依赖 C8 的任务取消传播；"真任务弹卡→界面四决定"完整交互——C8；无人值守交集闸门——M2/cron。
5. 开发中发现并修复的两个实现问题（非设计偏差）：跨线程 Future 唤醒竞态（HTTP 线程直接 set_result 不唤醒执行循环，改 call_soon_threadsafe）；演示脚本取"最新审批卡"的竞态（改带游标）。
