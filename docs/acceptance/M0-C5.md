## 0. 交付物清单

- **`agentcrew_core/tools/`** 四模块：
  - `metadata.py`：ToolMetadata（全字段：read_only/destructive/risk_level/needs_approval/concurrent_safe/side_effect_class/timeout_ms）+ Tool/ToolInvocation/ToolResult/WorkContext
  - `judgment.py`：判定纯函数——bash 只读三重判定（白名单 12 命令 × 元字符一票否决 × find 参数否决 8 token）、path_in_scope（realpath 规范，符号链接逃逸按真实路径判）、build_protected_paths（agentcrew.db/config.json/chain-head.txt/instance.lock/backups/logs/USER.md/soul.md/workspaces/*/MEMORY.md/~/.ssh/~/.aws）、host_allowed（精确 + `*.suffix` 通配，空=全拒）
  - `scheduler.py`：ToolRegistry（schemas() 出 Anthropic 工具定义）+ ToolScheduler（**非只读一律串行（全局锁）、只读/concurrent_safe 并行、信号量上限 4**；执行前后发 tool.prepared/dispatched/completed/failed 事件，载荷与 C2 投影契约对齐；input_hash=完整参数 sha256；call_id=uuid4）
  - `builtin.py`：五件套 + Seatbelt profile 构造 + 32KB 外部化
- **五件套**：
  - `read_file`：分页（行号 offset/limit，默认 200 行）
  - `write_file`：mkstemp 独占创建（不跟随预置符号链接、不拼 call_id 文件名）+ fsync + rename 原子写；prepared 载荷附内容 sha256（`content_sha256` 字段，verifiable 类核验依据；整体参数另有 `input_hash`）；发 artifact.created→ready 事件（产物投影唯一来源口径）
  - `bash`：判定结果进事件元数据（read_only_verdict/verdict_reason，闸门在 C6）；**所有执行套 Seatbelt 最小 profile**（写限 scope realpath / 网络全禁 / 凭据与受保护路径禁读——subpath 必须用 realpath，/tmp 符号链接实测踩坑后修正）；**env 白名单仅 PATH/HOME/LANG/TZ/TERM**；超时 killpg 杀进程组
  - `http_request`：allowed_hosts 判定；Idempotency-Key=(task_run_id:call_id) 派生；30s 超时
  - `ask_user`：发 question.requested/answered 事件 + 等待回答通道（ask_resolver 注入；挂起-回答全链 C8 接真实 HTTP）
- **输出外部化**：>32KB 落 `artifacts_dir/<call_id>.out` 并计 artifacts（created+ready 事件），结果留指针

## 3. 与设计的偏差及决策说明（外审回稿后修订）

1. **bash 的 ok 语义**：进程正常结束即执行成功（exit≠0 → ok=False、error=EXIT_N 但 output 仍带回 stdout）——命令级失败是"结果"而非"工具崩溃"，让模型自决（C8 失败状态约定）；仅超时/无法启动算工具级 error（TIMEOUT/TOOL_CRASH）。
2. ~~调度粒度更保守~~ **已按设计修齐**（外审建议 8）：concurrent_safe 的非只读工具（write_file/http_request）并行，仅 concurrent_safe=False 的非只读工具（bash 非只读命令）串行——测试补齐并发断言。
3. **Seatbelt 读取边界（如实）**：M0 profile 对受保护路径/凭据做了内核级禁读禁写（含落在 scope 内的情形，嵌套 subpath deny 实测压过外层 allow），但 scope 外的常规读取仍由判定层约束（白名单+审批），读取的完整强制边界 M2 收口——与 harness-design v1.9 边界声明一致。
4. **profile 的 subpath 必须 realpath**：/tmp → /private/tmp 符号链接导致规则匹配失效（实测发现并修正），scope 与受保护路径构造时统一 resolve（外审指出后者原先漏了，已修）。
5. **find -exec/delete 的"拒"在判定层**：判为非只读 → 需审批（C6 闸门）；C5 阶段调度层照常执行并携带 verdict 元数据（卡原文"被拒"指只读豁免被否决，实际拦截在 C6 接入）。
6. 未做项（按卡归属）：审批闸门（C6）、事件落库与工具结果回填循环（C8）、ask_user 挂起全链（C8）。
