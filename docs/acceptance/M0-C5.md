## 3. 与设计的偏差及决策说明

1. **bash 的 ok 语义**：进程正常结束即执行成功（exit≠0 → ok=False、error=EXIT_N 但 output 仍带回 stdout）——命令级失败是"结果"而非"工具崩溃"，让模型自决（C8 失败状态约定）；仅超时/无法启动算工具级 error（TIMEOUT/TOOL_CRASH）。
2. **调度粒度**：设计写"destructive 串行"；实现为"**非只读一律串行**"（含动态判定为非只读的 bash）——比设计更保守，避免非只读命令并行竞写；只读与 concurrent_safe 工具并行。
3. **Seatbelt 读取边界（如实）**：M0 profile 对受保护路径/凭据做了内核级禁读（实测 Operation not permitted），但 scope 外的常规读取仍由判定层约束（白名单+审批），读取的完整强制边界 M2 收口——与 harness-design v1.9 边界声明一致。
4. **profile 的 subpath 必须 realpath**：/tmp → /private/tmp 符号链接导致规则匹配失效（实测发现并修正），scope/保护路径构造时统一 resolve。
5. **find -exec/delete 的"拒"在判定层**：判为非只读 → 需审批（C6 闸门）；C5 阶段调度层照常执行并携带 verdict 元数据（卡原文"被拒"指只读豁免被否决，实际拦截在 C6 接入）。
6. 未做项（按卡归属）：审批闸门（C6）、事件落库与工具结果回填循环（C8）、ask_user 挂起全链（C8）。
