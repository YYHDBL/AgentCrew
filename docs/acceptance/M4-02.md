3. **计数资源双模式**：`tokenizer.py` 新增 `AGENTCREW_TOKENIZER_DIR` 显式资源目录——生产从 `<dir>/<prompt_format>/` 按固定 SHA 加载（缺文件/哈希不符在模型请求前明确失败），开发保持固定 revision 官方下载 + 可复现缓存。固定模型白名单校验未放宽（GLM 完整支持在 M4-09）。
4. **验证脚本** `scripts/release/verify_sidecar.py`：受限 PATH（`/usr/bin:/bin`）、独立工作目录、`HF_HUB_OFFLINE=1`（强制计数资源零网络来源）启动真实二进制。
5. **首次 soul 生成可靠性修复**（本卡核查中发现的真实现象）：aux 单发生成 soul 有字符配额（1215–1485），真实模型连续 7 次尝试 5 次长度不足（886/1060/1061…），导致新会话高概率失败。`_ensure_soul` 增加最多三次带自检字数的再生（配额校验本身不变，供应商务实错误仍单发失败）。本次核查中 2 次未达配额后第 3 次通过——机制按设计工作。
