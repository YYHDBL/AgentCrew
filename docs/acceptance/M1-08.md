# M1-08 · 结构化压缩、检查点与中断恢复

日期：2026-10-03，Asia/Shanghai。实施基础为 M1-07 `66fce8bacb564b01111a1403b546762a10639105`。实际 main、aux 均为当前有效配置的 `deepseek-v4.1-flash`，使用 M1-07 核查的官方 tokenizer 与 1,000,000 token 窗口。

## 压缩与持久化

每次前台模型请求之前检查历史预算，达到历史配额的 80% 即触发处理。system、当前任务指令、最近二十条消息及完整工具请求与结果组合保持原文。任务指令通过明确的任务身份保护；工具纠偏消息保留其消息角色。旧工具结果先完整保存到独立工件，保留前 2048 字节、路径、长度与 SHA；已有文件交付工件保持身份和内容。压缩归档的三个事件与工件投影在同一 SQLite 事务提交，重复处理验证已有文件并复用结果。

aux 对保护范围之前的历史及已有摘要生成五个必填字段：历史任务、目标、约束偏好、已完成动作及工具名、当前状态。输入、输出预留、保护区和压缩后请求均使用实际计数器核查。摘要格式错误、保护区超限、凭据风险和工件校验失败均明确终止当前请求。原始事件完整保留。

SQLite v8 的不可修改检查点保存摘要、保留消息、来源事件水位、替换范围、模板版本、模型与 usage、token 前后值、全部工件指针及冻结快照身份。检查点、`context.compacted` 和审计记录一起提交。恢复校验记录 SHA、关联事件、消息来源、快照及所有工件，再使用检查点和后续事件重建请求；副作用账本继续核对完整任务事件。损坏检查点或缺失工件通过 HTTP 返回可定位的 `409 REPLAY_CORRUPT`。
