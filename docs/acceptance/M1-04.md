# M1-04 · FTS5 历史与记忆检索

日期：2026-10-01，Asia/Shanghai。实施基础：M1-03 `3639873aa394dcfa8a292a5249d9a0e09c092217`。本卡交付 messages_fts、memory_fts、session_search 工具及真实身份下的中文检索。

## 实现与回归

SQLite v5 使用 FTS5 trigram 外部内容索引。消息和记忆条目插入、修改、删除时，触发器在业务事务中同步索引。迁移为既有记录建立索引；显式重建通过串行写入通道执行，并核对索引与外部内容一致。缺少 FTS5 或 trigram 时，真实建表语句立即导致迁移失败，既有启动诊断机制阻止业务运行。本机实际能力、建表语句与迁移记录见 [sqlite-capabilities.json](assets/M1/04/sqlite-capabilities.json)。

查询去除首尾空白，至少三个 Unicode 字符执行参数化字面短语 MATCH，更短查询执行参数化 instr。引号经过 SQLite 字面短语转义。两条路径使用相同工作区、员工、审核、防护、归档和分页规则；消息来自真实会话，记忆来源包含稳定身份、首行哈希、当前修订、依据和原始来源。归档会话仍可检索，记忆归档正文需要显式 archived 参数。

检索持有三库读取锁，并先验证正文与 metadata 的文件 SHA。未经审核的高风险条目及包含注入的正文、依据、审核依据不进入结果；历史中的指令性模式同样过滤。工具执行范围从真实 task_run 和 conversation 读取，调用者不能通过附加参数更换范围。结果按 created_at、id 降序，同时间及同身份使用 kind 维持稳定次序；游标绑定查询及身份，排他读取，分页上限 200。

显式记忆命中使用独立统计，call_id 与 entry_id 唯一去重；去重记录和累计统计在同一个真实 SQLite 事务内提交。检索不改变正文、metadata、业务修订或会话冻结快照。

检索测试 **13 项通过**，涵盖中文两种查询、五条历史分页、归档会话、身份隔离、引号输入、历史更新与删除、记忆修改与归档恢复、人工审核、外部修改、注册工具身份、v4 真实原数据升级、消息和记忆碰巧同时间及同身份的分页、并发命中去重和无模型调用。检索、快照、存储、迁移与启动联合回归 **61 项通过，7.76 秒**，见 [search-tests.txt](assets/M1/04/search-tests.txt)。最终后端全量回归 **460 项通过，1 条既有 Starlette 弃用警告，124.70 秒**，见 [backend-tests.txt](assets/M1/04/backend-tests.txt)。OpenAPI 检查通过，见 [openapi.txt](assets/M1/04/openapi.txt)。
