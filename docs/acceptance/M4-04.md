## 实现

1. **契约先行**：`docs/contracts/openapi.yaml` 新增 `POST /api/settings/models/verify`（每槽计数资产 + 真实小请求结果，脱敏）、`Settings.catalog`（服务端受控已知模型目录）与 `ModelSlot.base_url`；类型重新生成，`check:api` 通过（91 paths）。
2. **后端**：`SettingsService.get_view` 增加 `base_url` 与 `catalog`（DeepSeek 条目含经核查的窗口/revision/SHA；GLM 条目如实标记计数未核查）；PATCH 后新密钥立即进入脱敏登记表（补齐启动期登记的盲区）。新增 verify 端点：本地计数资源检查（不触网）+ 对配置端点的一次真实小请求（15s 超时、固定 `settings-verify` 会话标识满足 ADR-010 路由头要求），错误分类并经 `redact` 脱敏。成员对 `GET /api/settings` 只读放行，PATCH/verify 仍限 owner。
3. **前端**：新增 `ModelSettings.tsx` "模型连接"设置页——已知模型一键套用到 main/aux（元数据不可手填）、协议/模型/地址/密钥编辑、密钥只显尾 4 位且空值保持、显式清除（确认弹窗）、保存/验证双动作（明确区分"配置已保存"与"连接验证通过"，展示验证产生的真实请求说明）、env 覆盖提示、成员只读。保存按"输入即所见"提交（清空地址即清除自定义地址；openai-compatible 空地址被服务端 422 明确拒绝）。工作台在未配置时提示"模型连接尚未配置"并提供直达入口；配置保存后提示即时刷新（不重复引导）。
4. **顺带修复的真实缺陷**：antd `loading` 会把 "loading" 注入按钮无障碍名导致名称不稳定且状态残留——保存/验证按钮改为稳定名称 + 消息区提示；`aria-busy` 不再覆盖保存中的表单（此前会把整个表单移出无障碍树）。
