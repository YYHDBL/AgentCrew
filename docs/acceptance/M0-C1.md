## 0. 交付物清单

- `backend/pyproject.toml`（uv 管理；依赖 fastapi/uvicorn/sse-starlette/pydantic/httpx；SQLite 用内置 sqlite3——M0-cards §3 选型；`uv.lock` 已入库）
- 分包骨架：`agentcrew_core/`（events/loop/tools/provider/recovery/ports，占位 docstring 标注填充卡号）+ `agentcrew_server/`（api/db/run_manager + cli/config/logging_setup/secrets/instance_lock/lifecycle/runtime）
- 入口 `python -m agentcrew_server --port N --data-dir D --parent-pid P`（读 `AGENTCREW_TOKEN` 环境变量）
- 启动序列按 backend-service.md §1（instance.lock → SQLite(WAL) → 后置挂钩[迁移/审计链校验/对账=C2/C9 诚实占位日志] → 端口探测 → listen → stdout `AGENTCREW_READY {"port":N}`）
- 配置链 env > data/config.json > 默认（纯函数 + 参数化单测；env 覆盖字段列表供 C7 ignored_fields 使用）
- CORS allow-all（安全由 Bearer 承担，§5）；统一错误信封中间件 + 错误码表（§6）；`GET /api/health`
- 日志：`data/logs/sidecar.log` 轮转 5MB×3 + stderr，机密值脱敏 Formatter 兜底
- SIGTERM/SIGINT 优雅关闭（§7 子集：停收→[任务/SSE 随 C8/C3]→WAL PASSIVE checkpoint→关库→[链头快照 C2 占位]→释放锁→exit 0）
- parent-pid 看护（父进程退出→优雅自杀）

## 5. 优雅关闭（SIGINT / SIGTERM → exit 0）

```
$ kill -INT <python pid>
$ cat exit-i
0
$ grep 'shutdown\.' data-i/logs/sidecar.log
… INFO agentcrew.server shutdown.begin 优雅关闭（总预算 10s；停收新请求由 uvicorn 完成）
… INFO agentcrew.server shutdown.checkpoint wal_checkpoint(PASSIVE) busy=0 wal_frames=0 checkpointed=0
… INFO agentcrew.server shutdown.db closed
… INFO agentcrew.server shutdown.step 链头快照：C2 交付（audit_log 未建，跳过）
… INFO agentcrew.server shutdown.done
… INFO agentcrew.server shutdown.signal 收到信号 [2]，已优雅关闭
… INFO agentcrew.server shutdown.exit 正常退出（exit 0）

$ # 锁已释放验证：同 data-dir 立即重启 → READY 正常 → kill -TERM → exit 0
AGENTCREW_READY {"port": 8716} … exit-i2=0
```

实现注记：uvicorn 0.54 在优雅关闭后会**恢复原 handler 并重抛捕获的信号**（首次验收实测退出码 143）。为满足 §7「优雅关闭 exit 0」，在 uvicorn 安装自身 handler 前先安装我方记录型 handler 吞掉重抛信号——修复后 SIGINT/SIGTERM 均实测 exit 0。

## 8. 与设计的偏差及决策说明

1. **错误码表补 4 项**（UNAUTHORIZED 401 / METHOD_NOT_ALLOWED 405 / VALIDATION_ERROR 422 / INTERNAL_ERROR 500）：统一错误信封中间件对框架异常（404/405/422/未捕获）需要 code 值。已按"先进表再实现"纪律同步进 backend-service.md §6（v1.2）。
2. **缺 AGENTCREW_TOKEN 拒绝启动（退出码 1）**：设计未明写缺失时的行为；按 fail-closed 姿态（harness-design §5）选择拒绝启动而非裸跑，理由：无 token 的 sidecar 可被本机任意进程调用，权限体系整体失效。
3. **uvicorn 信号重抛适配**（见 §5 实现注记）：不改变设计语义，属实现层对第三方行为的对齐。
4. 任务卡文中"错误信封（§4）/优雅关闭（§6）/CORS（§3）"为 v1.0 节号，对应本文 v1.2 的 §6/§7/§5，按内容对齐执行，无实质冲突。
5. 日志轮转 5MB×3 的参数已装配（RotatingFileHandler maxBytes=5242880, backupCount=3）；轮转行为需 ≥5MB 日志量才可观察，本卡不人为灌水演示（后续卡片长跑自然覆盖）。
