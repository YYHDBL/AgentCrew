# M4-03 生产启动、监管与数据路径

日期：2026-10-10，Asia/Shanghai。判定：**通过**。

## 实现

1. **生产启动分支**（`desktop/src/main/sidecar.ts`）：`app.isPackaged` 时以绝对路径启动 `process.resourcesPath/sidecar/darwin-<arch>/agentcrew-sidecar`，注入 `AGENTCREW_TOKENIZER_DIR=<resourcesPath>/tokenizers`；启动前校验可执行文件存在与 X_OK 权限、计数资源 manifest 存在，缺失立即写日志 + 弹窗给出具体路径与日志位置，**不回退开发命令**。Finder 场景不依赖 PATH/工作目录（独立可写 cwd）。
2. **开发分支保持仓库 uv 启动**；新增 `AGENTCREW_SIDECAR_BINARY`/`AGENTCREW_TOKENIZER_DIR` 覆盖，**仅在未打包时生效**，供本卡用真实打包产物驱动监管检查；生产对这些环境变量免疫（资源路径只来自 `process.resourcesPath`）。
3. **启动/重启去重**：`Sidecar` 增加单一生命周期队列，并发 `start`/`restart` 串行执行，同一时刻至多一个启动流程；已在运行的 `startOnce` 直接返回。
4. **稳定数据路径**：主进程入口 `app.setName('AgentCrew')`，userData 固定为 `~/Library/Application Support/AgentCrew`（开发与打包一致；测试 `--user-data-dir` 不受影响），sidecar 数据、日志、启动日志均在其下。
5. **渲染边界**：`ELECTRON_RENDERER_URL` 仅在未打包时生效——生产只加载包内 renderer，外部注入的渲染地址不构成攻击面。contextIsolation/sandbox/禁 nodeIntegration/窗口开闭边界维持原状。
6. **可定位性补全**：自动重启达上限时先在启动日志写入明确记录再弹窗（此前该事件只出现在弹窗、日志无痕，本卡实证发现）。

## 核验记录

`npm run typecheck && npm run build && node tests/m4-sidecar.mjs`（真实 Electron + M4-02 真实打包 sidecar，按 pgid 识别 onefile 父子进程组；证据：[m4-sidecar-report.json](assets/M4/03/m4-sidecar-report.json)，17 项检查 0 失败）：

- 端口占用：请求端口被占时真实二进制在 +1..+3 内换端口就绪，SIGTERM 优雅退出 exit 0。
- 首次就绪单实例；SIGKILL 进程组后自动重启（新进程组、新端口）；**旧令牌对数据接口 401、新令牌 200**（`/api/health` 供壳健康轮询本就不鉴权，令牌语义在 `/api/settings` 上核查）。
- 并发 restart 去重后仍单实例；端口与令牌每次轮换。
- 二次启动被单实例锁拒绝（exit 0），既有窗口保持可见，无第二个任务服务。
- 确认退出后应用 exit 0、sidecar 无残留；父进程 SIGKILL 后 sidecar 自行退出（无孤儿）。
- 真实慢启动进程（45s）触发 30 秒预算真实计时失败；不可执行路径按 1s/2s/4s 阶梯重启至上限后停止并记录，无残留。

## 过程中的真实缺陷（已修复）

- onefile 父子两进程同 cmdline，按进程计数会误报双实例——按进程组计数后语义正确。
- 重启上限事件只进弹窗不进日志（上述第 6 点）。
- 测试侧 `once('exit')` 竞态与 `await` 语法问题属检查自身缺陷，已修复。
