# M1-11 · 管理 API、鉴权与事件重放

日期：2026-10-03，Asia/Shanghai。实施基础为 M1-10 `47f2ae150f961c81dd8742ccffc0525d9b895f35`，唯一交付分支为主仓库 `desktop-shell`。

## 接口与作用域

全部 M1 管理接口已经接入正式 FastAPI 应用。三库和 Skill 管理支持原文与 metadata 查询、状态过滤、条目创建及编辑、固定、取消固定、归档、恢复、人工审核、完整账本分页和历史内容恢复。Skill 创建由服务分配身份，修改与支撑文件读取继续核查目录和修订。历史与记忆检索复用 trigram 和参数化短查询。后台作业分页包含独立审批、调用记录、usage、报告和实际错误；作业取消、审批决定和手动治理沿用已验收的生命周期服务。

管理请求使用当前所有者身份，明确提供工作区及员工范围；范围须来自既有会话或 Skill 登记。USER 为所有者共享库，工作区限定在当前工作区，soul 和 Skill 同时核查员工。指定来源会话时还须匹配来源范围。后台按标识查询允许所有者读取，提供当前工作区及员工参数时强制匹配两项，禁止部分范围参数。所有请求复用既有 Bearer 鉴权及诊断模式守卫。

Pydantic 校验请求结构、必填字段、真实整型修订、合法标识和额外字段。change_id 的首次结果绑定动作、条目哈希、账本身份及完整请求，重复请求返回首次提交结果，其他目标或输入返回 409。正文修改改变首行时保留 entry_id。Skill 管理编辑在读取当前正文之前核查已有幂等结果，使旧哈希的相同请求能够读取首次结果；陈旧修订、哈希冲突、外部修改、配额及审批失效均返回可定位错误。

条目按创建时间及身份正序，Skill 按名称及身份正序，账本按 id 降序，作业按创建时间及身份降序分页。游标绑定当前身份、范围、状态过滤和排序，排他返回后续记录；正文条目游标同时绑定整库修订。分页默认五十，上限二百。文件缺失、metadata 符号链接或目录替换、正文 UTF-8 损坏均明确返回文件冲突，保留磁盘原状。

## 真实 HTTP 与契约核查

完整 CLI 服务使用独立真实运行库，通过实际 TCP 发出 **42 次 HTTP 请求**。覆盖所有 M1 管理 operation，包括三库读取/创建/编辑、DELETE 归档、四种状态变更、人工审核、账本查询及恢复、中文检索、Skill 创建/索引/支撑文件、作业查询/取消/审批与异步治理；额外核查 Settings GET/PATCH。每条成功和错误响应均使用成熟 JSON Schema 实现核对当前 OpenAPI。并发编辑实际得到一次 200、一次 409；相同 change_id 重放返回首次结果，输入改变返回 409。Scope 越界返回 403，鉴权失败返回 401，分页超限和不匹配游标返回 422，路径穿越返回 403，旧审批返回 409。

实际 SSE 从全局水位 1651 注册后接收变更事件 1652；断线使用同一排他水位重连，取得相同已提交事件，没有伪造前台 task_run_id 或 seq。完整请求、响应、操作标识、schema 核查结果、SQL、文件 SHA/纳秒 mtime、事件水位及审计见 [management-http.json](assets/M1/11/management-http.json)。管理前后 llm_calls 均为 **144**，两级审计 459 条通过，服务退出码 0。

针对性回归使用真实 uvicorn、HTTP 客户端、文件和 SQLite，包含连续十六次修改期间的补播与实时交接，核对事件无遗漏、无重复；断线后排他续播。另一员工的私有 soul 更新未进入当前流，同工作区共享事实正常返回。独立审批通过实际 HTTP 核查重复决定和取消失效，所有者请求不能把已完成前台任务变成等待审批。
