## 0. 交付物清单

- **进程内事件总线**（`agentcrew_server/bus.py`）：会话/任务/全局通配三种话题；订阅表线程安全（写通道线程发布 × 事件循环线程消费）；每连接队列上限 1000（溢出置标记不静默丢帧）；并发 SSE 连接上限 32（`ConnectionLimitError` → 503 SSE_LIMIT）；`shutdown_all()` 扇出控制帧；死连接宽限 5s 强断（防泄漏）
- **Bearer 鉴权中间件**（`api/auth.py`）：`hmac.compare_digest` 比较；无/错/格式坏 → 401 UNAUTHORIZED（错误信封）；仅 `/api/health` 豁免（契约 security: []）；CORS 预检由最外层短路
- **SSE 两端点**（`api/sse.py`，sse-starlette）：
  - `GET /api/conversations/:id/stream?from=<global_seq>` 与 `GET /api/task-runs/:id/events?from=<seq>`
  - **无遗漏交接**（backend-service §3）：先注册实时订阅（带缓冲）→ 只读连接读历史至已提交 head → 转实时，缓冲中 global_seq ≤ head 的帧丢弃
  - 流首 `retry: 3000` 建议行；心跳注释行（ping=15s）；数据帧 = 事件信封 JSON
  - 控制帧 `event:resync`（data 含最后连续游标；任务流另带 task 内 seq）与 `event:shutdown`（含游标）
  - 订阅不存在的会话/任务 → 404（信封）；连接超上限 → 503 SSE_LIMIT
  - 任务事件 JSON 分页模式（`after_seq` 排他 + `limit ≤ 500` → `{data:{items, next_after_seq}}`，契约已有）
- **接线**（cli/runtime）：常驻 `EventStore(publisher=bus.publish)`——发布在写通道线程内、COMMIT 之后同步入队（发布顺序 = 提交顺序，§2 v1.9）；`_GracefulServer` 把 shutdown 帧投递挂到 uvicorn `handle_exit` 首行
- 验收驱动脚本 `scripts/seed/c3_acceptance.py`（`--seed-only` 供外部演示灌历史）

## 4. 与设计的偏差及决策说明

1. **shutdown 帧投递时点（实现层修正）**：uvicorn 的关闭顺序是"先等连接结束、后跑 lifespan"——若按直觉把 `bus.shutdown_all()` 放 lifespan，SSE 长连接与关闭流程互等，帧永远送不到（实测复现）。修正为子类化 `uvicorn.Server`，把帧投递挂到 `handle_exit` 首行（信号处理的第一时间），帧先于连接等待入队。契约语义不变。
2. **"服务端终止连接"的可见语义 = 流终止**：uvicorn 自管 hop-by-hop 头（应用层 `Connection: close` 被忽略），SSE 流结束后 socket 进 keep-alive 池、约 5s 空闲超时才 FIN。客户端（EventSource/curl）在响应流结束（chunked 终止块）时刻即退出，无需等 FIN。验收按"resync 后不再有任何数据帧"断言（驱动与单测一致）。
3. **慢消费者溢出的触发链**为 uvicorn FlowControl 背压（asyncio 写缓冲 >64KB → send 阻塞 → 生成器停摆 → 队列打满），纯内存缓冲不足以触发——验收数据量按穿透内核缓冲（~200KB）+ 灌满队列（1000×~300B）设计，实测有效。
4. 全局通配订阅（Topic "all"）为总线内部能力，M0 未暴露端点（无契约对应）。
5. `/api/diagnostics` 自本卡起需 Bearer（契约全局 security，未豁免）；C2 验收时无鉴权层属当时能力范围。

| # | 发现 | 处置 | 落点 |
