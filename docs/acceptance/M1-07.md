# M1-07 · 上下文预算与工具输出工件化

日期：2026-10-03，Asia/Shanghai。实施基础为 M1-06 `b05ebd04f6e5a4c9e5f8d2cba1ba15d5414b8c00`，交付分支为主仓库 `desktop-shell`。

## 请求预算与计数依据

每次 main/aux 模型请求在进入供应商流之前，使用已核查的 DeepSeek V4.1 官方消息编码和 `tokenizers` 对实际请求结构计数。计数包含 system、三库冻结内容、Skill 索引、九个工具声明及其 JSON Schema、历史、thinking、工具调用参数、工具结果和预留的 `max_tokens`。system 与工具声明最多使用实际窗口的 15%，历史最多使用 60%，工具结果与输出保留至少 25%。完整输入加最大输出须容纳在窗口内。每次检查均写入 `context.budget_checked` 事件并记录不含私密正文的数量、模型、来源与版本；超限和计数依据缺失时在供应商 HTTP 请求前明确报错。

当前实际服务为 OpenCode Go 的 `deepseek-v4.1-flash`。其[提供商模型元数据](https://models.dev/api.json)记录 1,000,000 token 上下文窗口及 384,000 token 输出上限；来源摘录和原响应 SHA 见 [model-window-source.json](assets/M1/07/model-window-source.json)。官方模型仓库修订固定为 `2cba9e42aa026125f3ed06c6d98c1db82f7ca027`，`tokenizer.json` SHA-256 为 `c90dfa01249db1be4245780a052ede752e1361c612ac6d08e2bdada7d599476b`，已逐行核查的 `encoding/encoding.py` SHA-256 为 `502bdaec8a3fd88ebc24c4721a7038fbe42f2063c664638127056107920035c1`。运行时固定来源和完整文件哈希后才加载编码实现。当前有效模型及端点自动绑定这组已核查描述符；其他模型、端点或不匹配的显式配置返回 `TOKENIZER_UNAVAILABLE` 或 `MODEL_WINDOW_UNKNOWN`。

真实 main/aux 各发送一次不带工具的请求，官方计数与供应商 `prompt_tokens` 均相同。实际 main 声明九个工具时，计数为 1561，供应商报告 1557，相差 4 token；持续采用该保守值校验窗口。三个真实请求的身份、计数、usage 及来源见 [model-usage.json](assets/M1/07/model-usage.json)。另一次真实 HTTP 会话中，前台两个任务各进行两次模型请求，包含工具结果的请求依次记录预算事件及供应商 usage；数值见 [http-model.json](assets/M1/07/http-model.json)。该会话的模型请求差值同为 4 token。

## 完整工件与恢复

工具注册表的 `max_output_bytes` 与现有 32KiB 内联阈值共同决定工件化。`read_file` 的选中分页、子进程 stdout/stderr、HTTP 响应都先完整写入有界内存缓冲；达到阈值后缓冲转入任务工件目录。服务层在同目录写入唯一临时文件，flush、fsync、原子替换并同步目录。上下文仅保留 UTF-8 安全的前 2048 字节、工件路径、完整字节长度及 SHA-256；`artifact.created`、`artifact.ready`、`tool.result_externalized` 和工具终态事件带可追踪的调用身份与来源事件水位。工件目录不可写、原文件损坏或哈希不一致时明确失败。

真实 HTTP 会话 `f6b16fda75a74b3fabb4014dc3fd6f86` 的任务 `5d8c9590d52247de944fa6f95d6a37ab` 调用 `read_file` 读取 408,000 字节中文资料，保存的工件字节及 SHA `4038d59373e3e77b067b2d3f84ef33c8e8fee0edd85ecad480815a49199e09cc` 与源文件一致。第二个任务 `79d8294aefc54d14bb974aa4da48d95a` 再次读取该工件并保存完整结果。两个 `tool.result_externalized` 事件各自引用真实 `tool.dispatched` 水位，前缀分别不超过 2048 字节。供应商请求包含可校验指针，没有包含完整资料。源文件与冻结快照的 SHA/mtime、事件 SQL、作业记录、六个真实供应商请求及审计结果均在 [http-model.json](assets/M1/07/http-model.json)。审计链及锚点共 61 条核验通过，服务退出码 0。

该会话通过实际 HTTP 设置未知模型后发送第三个任务 `931c643e1b2a46b683326349d9c63985`；任务返回 `TOKENIZER_UNAVAILABLE`，记录 `llm.request_failed` 与 `run.failed`，没有发出该模型的供应商请求。随后通过 HTTP 恢复有效模型配置。独立恢复回归使用真实文件、SQLite 事件与 HTTP 服务，在工件被修改和删除时分别得到 `409 REPLAY_CORRUPT`、`ARTIFACT_HASH_MISMATCH` 和 `ARTIFACT_MISSING`，任务保持 interrupted；结果见 [resume-tests.txt](assets/M1/07/resume-tests.txt)。
