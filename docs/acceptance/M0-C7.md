## 3. 与设计的偏差及决策说明

1. **can_queue 计入 starting**（文档已同步 §4 真值表）：卡内失败状态"并发同会话两条指令（锁序化，第二条必入队）"要求指令直发后、run.started 落库前的第二条指令入队而非被拒——§4 原文 `state == running` 按字面会在 starting 相位把第二条指令 409 掉。
2. **run_events.task_run_id 放开可空**（迁移 v2 表重建，文档 §2.1 已同步）：C2 建表误加 NOT NULL（设计原文是 `task_run_id FK`）。queue.* 是会话域事实，暂停态下取消排队项时没有任何运行中任务可锚；锚到无关任务会污染任务级 SSE 流与 attempts 重建。表重建显式保序复制 global_seq（升级游标不漂移，有专门单测）；UNIQUE(task_run_id, seq) 改部分唯一索引，任务事件语义不变。
3. **全部材料被拒的判定含 folders**（契约 422 描述只写了文件）：文件夹与文件同为"任务创建时提供的材料"，全部被拒仍建任务会让 agent 拿不到任何被许诺的访问——对称处理，422 不建任务。
4. **出队指令的消息行在入队时写**（run.queued 带 queue_item_id 时投影跳过重写）：避免同一条指令两条 user 消息；重放一致（两处投影都由事件派生）。
5. **审计与配置文件的原子性取舍**（settings.py 注释）：§4 只约束"文件写失败→500 且内存不变"；审计链 append-only 无法回滚，取舍为先写文件→提交后入审计——审计失败如实告警不回滚文件（文件与内存已是新值）。该窗口仅在 SQLite 提交失败时出现。
6. **state_badge 的 idle 细分**：idle 时取会话最近任务状态映射 interrupted/failed 徽章（契约枚举），否则 idle；starting/running 统一徽章 running。
7. **既有测试适配**（非行为变更）：Database 读连接统一 `row_factory=sqlite3.Row`（列名访问，下标访问全兼容——6 处既有断言从 `row == tuple` 改 `tuple(row)`）；迁移版本断言 v1→v2。
