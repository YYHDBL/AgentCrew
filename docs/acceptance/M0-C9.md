## 0. 交付物清单

- **启动对账**（`agentcrew_server/recovery.py` `RecoveryService.reconcile`，lifespan 内、RunManager 派发协程之前执行）：
  - 扫描口径 = task_runs 全部非终态 `queued / running / waiting_user / waiting_verification`——覆盖 C8 外审 F1 附带风险（优雅关闭把名额等待中的 queued 任务留在库中，只扫 running/waiting_user 会永久卡死会话）
  - 补中断按**当前收敛状态**判定（状态 → interrupted，**不隐式重启**；外审回稿 F1 修订，见 §6）：`queued/running/waiting_user` 必补（resume 成功回 running 后再崩同样补，历史事件不作已收敛证据）；`interrupted`（已收敛）与 `waiting_verification`（已有待核验闸挡着）不补——后者重发会让 FSM 已回 idle 的会话 InvalidTransition 打死 replay
  - 结清 dispatched 无终态调用，顺序为**先 interrupt 后结清**（反过来 run.interrupted 投影会把 waiting_verification 盖回 interrupted）：`ask_user` 豁免（§6.2 v1.8：账本停 dispatched、不转待核验）；`verifiable` 且 prepared 带 content_sha256 → stat 真实文件 + sha256 核对，**存在且一致补 tool.completed（自动核验补完）**，不存在/不一致/没哈希 → pending_verification；其余（含 outcome_unknown）一律 pending_verification
  - `tool.pending_verification` 投影新语义（事件派生，rebuild 稳定）：非终态任务转 **waiting_verification**；终态任务不翻（C8 _finish 先结清再落终态的顺序天然兼容）
- **上下文重放器**（`agentcrew_core/recovery/replay.py`，纯函数参数化单测）：
  - `replay_messages(rows, read_artifact)`：以 llm.request_done 载荷（回复全文 + 全部 tool_use 块 + thinking 签名，v1.7）为唯一原料重建消息上下文，tool 终态事件配对 tool_result；超限输出按 §2.3 读工件文件，缺失 → "工件缺失"占位降级（任务继续 + 告警）
  - 中断无终态的调用按账本事实合成占位：ask_user 未回答 → "（中断，未回答）"（§6.2 v1.8，告知可再问；重启后补答过的用真实回答）；prepared 未派发 → "（中断，未派发执行）"；dispatched → "（中断，执行结果未记录）"；核验结论 → "经用户确认已执行；原始输出未记录" / "（该调用未执行，需要时应重做）"
  - **损坏事件行**：跳过 + 显式告警 + `needs_manual_review`——resume 前置校验据此 409 REPLAY_CORRUPT（新错误码，ErrEnvelope 自由字符串域）拒绝自动恢复，任务留 interrupted 交人工，绝不静默
  - `side_effect_ledger(calls)`：§7 两段系统提示文本（账本"你已执行：X；未执行/结果不明：Y" + 恢复指令常量）
- **resume**（`POST /api/task-runs/:id/resume`，202 无响应体）：
  - 前置校验（会话锁内，与直发/排队/继续同一串行域）：任务须 interrupted/waiting_verification；本任务存在 pending_verification → **409 PENDING_VERIFICATION 带清单**；重放损坏 → 409 REPLAY_CORRUPT 带 warnings；会话 FSM 非 idle（另一任务在跑）→ 409
  - `RunManager.start_resume` 发 `run.resumed {attempt_no, attempt_id, resume_reason, context_fingerprint}`（与 run.started 同源 `_assemble_attempt` 计算指纹——"每次 attempt 记 context_fingerprint" 对 resume attempt 同样成立；projections 头部契约已登记新字段）→ 总线派发 **resume runner**（C8 移交项：_runner 原只认 queued，现 RUN_RESUMED 派发路径接通）
  - resume runner：不发 run.started（attempt 行由 run.resumed 投影建立）；messages = 重放重建 + system 尾部注入两段账本/指令；**attempt_no 与回合号跨 attempt 续接**（`_next_ordinal`：steps(task_run_id, ordinal) 唯一、回合上限 40 按任务计——重置会撞唯一约束并使预算翻倍，真实 kill -9 首跑抓到后修复，LoopDeps.start_ordinal）
  - resume 后模型新发起的调用 = 新 call_id 正常过闸门（绝不自动跳过；防重复靠账本可见性 + 核验闸，§6.2 v1.2）
- **核验提交**（v1.4 F003）：`GET /api/conversations/:id/pending-verifications`（call_id/工具/参数/dispatched_at/证据——verifiable 类**把核验结果写进证据**：GET 时真实 stat + sha256，"文件不存在/哈希一致/不一致"三种结论）；`POST /api/tool-calls/:callId/verification`（confirmed_executed → completed(verified_by_user)；confirmed_not_executed → not_executed；事件 + 审计链单事务；非待核验态 409）
- **取消补全**：`request_cancel` 对 interrupted/waiting_verification 任务真正落 run.cancelled（原实现把 interrupted 当终态 no-op）；配套 reducer 扩展：**run.cancelled 自 idle 起合法**（对账后 FSM 已回 idle，不扩展则 emit_cancel_pair 会让该会话 replay 永久抛 InvalidTransition）——同一队列暂停规则
- **artifacts**：`GET /api/conversations/:id/artifacts?task_run_id=`——missing 惰性探测（ready/generating 行 stat 真实文件，不存在 → 发 artifact.missing_detected + 状态转 missing；已 missing 不重复发）
- **SSE 慢消费者测试加固**（C8 移交小项，历史三次时序 flake）：去掉固定 `sleep(0.3)`（改为轮询订阅 `last_sent_global_seq` 确认历史段真实送达）与 1.5s 时钟窗口收尾（改为等 **chunked 终止块 `0\r\n\r\n`** 这一协议事实）——真实背压法（SO_RCVBUF 压缩 + overflowed 标志观察保留）
- **llm.request_done 载荷契约锁定测试**：逐字段核对 loop 发射载荷（9 键全集 + tool_uses/thinking_blocks 嵌套形状 + delta 拼接全文）——恢复重建唯一原料的字段漂移即红
- **装配**：cli 构造 RecoveryService 并双向 wire（recovery.wire(run_manager) / run_manager.wire(recovery)）；lifespan 先对账后启动派发协程；lifecycle.py 占位清理（对账迁走，只剩 M2 种子）；openapi 无需改动（四端点 v0.3 已有，`check_openapi.py` 29 paths 通过）

## 3. 与设计的偏差及理由

1. **reducer：run.cancelled 自 idle 起合法**（harness-session §4 迁移表原文只列 starting|running）。理由：C9 要求 cancel 可放弃 interrupted/waiting_verification 任务，而这两态的 FSM 已被 run.interrupted 收敛回 idle——不扩展则 emit_cancel_pair 会让该会话的 `_fsm_sync` replay 永久抛 InvalidTransition（每次快照都死）。迁移表注释已同步登记；同套队列暂停规则。§4 未列此行，属设计补录。
2. **run.resumed 载荷新增 context_fingerprint**（projections 头部契约原只列 attempt_no/attempt_id/resume_reason）。理由：v1.7"每次 attempt 记 context_fingerprint"对 resume attempt 同样成立，且与 run.started 同源计算零额外成本；已按"新增字段先登记再使用"纪律登记。
3. **场景 A 的 kill 点选在 ask_user 挂起（waiting_user）**而非轮询竞抢两次工具调用之间的毫秒窗口。理由：同属"任务跑到工具调用间隙"（a.txt 已完成、b.txt 未开始），且挂起点确定性可等——毫秒窗口在演示里不可稳定复跑。卡面要求的三个判据（对账 interrupted / resume 后完成 / 文件无重复写入痕迹）全部覆盖。
4. **"账本告知模型该调用未发生"在演示中为结构断言**（核验事件、not_executed 账本行、resume 后模型事实上重做了 sleep——读账本后行为与"被告知未执行"一致），账本/占位文本由单测锁定（`side_effect_ledger` / `replay_messages` 占位矩阵）。理由：ADR-006 纪律——不断言模型措辞；系统提示注入内容无 API 可观测面。
5. **待核验清单响应含 task_run_id 字段**（契约 PendingVerification 未列，schema 未禁附加属性）。理由：前端核验卡需要知道归属任务；如外审认为应收窄再裁。

## 4. 已知边界（不属本卡）

- resume 的 token 预算按 attempt 重新计数（回合上限已跨 attempt 连续；token 累计跨 attempt 归并在 M1 压缩一并做）。
- 重放只重建任务内上下文 + 同会话已完成任务的（指令，回复）对沿袭 C8 口径；若 resume 前同会话有新任务完成，其交换不进本任务重放上下文（与 initial 口径一致）。
- 场景 A 中驱动器会把 kill 前遗留的旧提问也补答一次（QuestionService 孤儿补答路径，事件留事实，无行为影响）。

## 5. 验收结论

两段真实 kill -9 验收全过（20/0）：账对得上（对账收敛 + 不双终态 + 不隐式重启）、活能接着干（重放重建 + 账本注入 + 回合号续接）、副作用不重复（verifiable 哈希核验 / 待核验闸 + 409 / not_executed 告知重做 / mtime 与 prepared 计数为证）。M0 引擎核心能力（C1-C9）至此齐装。

### 已知语义说明（K2）：指纹的记录时刻

resume 的 `context_fingerprint` 在 `start_resume` 里、拿到会话锁后立即计算并随 `run.resumed` 落 `run_attempts`——记录的是**恢复请求（点击）时刻**的配置快照；initial 的 `run.started` 发生在 runner **取得全局并发名额之后**（C8 建议④），记录的是名额后时刻的快照。二者在无并发 PATCH 时一致；有 PATCH 时，resume 的指纹（审计语义 = 用户点击时所见配置）可能与名额后实际运行绑定（gates/models 仍在 runner 装配处、名额后绑定）不同源。这是已知且有意保留的差异：C8 同款闸口径（等待期 PATCH 被本次 attempt 吸收、以名额后快照运行）不受影响，指纹字段以"记录请求时刻"为审计用途，不承担运行绑定的证明职责。
