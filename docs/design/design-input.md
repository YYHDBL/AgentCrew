# AgentCrew 设计输入包

> 本文供 UX Agent 绘制线框图与 Figma 视觉稿。页面职责以 [产品定义](../product/PRODUCT.md)、[用户流程](../product/USER-FLOWS.md) 和 [功能规格](../features/) 为准。UX Agent 负责交互布局与视觉细节，Frontend Agent 根据确认后的设计实现界面。

## 设计方向

仅设计 macOS 桌面端，界面使用中文、浅色、简约的苹果风格。任务内容与当前操作占据视觉重点。参考图 [浅色概念图](../assets/agentcrew-desktop-light-concept-v1.png) 只提供气质和布局启发；线框图要根据用户流程决定信息位置。视觉系统可沿用现有 React、Ant Design 组件基线，通过主题变量与必要的样式实现一致的桌面体验。

## 页面与区域

工作台左侧展示新建任务、可用工作空间和最近任务；任务列表与整条左侧栏都可收起。中间展示任务标题、员工、状态、指令、回复、执行概览、审批、排队及产物，底部固定输入区。右侧运行详情可收起，展开后按时间展示步骤与工具信息。左侧与右侧收起时，当前状态、待审批入口、新建任务和输入区仍可找到。窄窗口应继续支持完整任务操作。

运行中心负责跨任务查找、事件时间线、回放和审计报告；数字员工管理页负责岗位、技能、连接器、记忆和已授权范围；管理中心负责演示身份、角色与资源授权、审计查询和只读诊断；自动化页面负责定时配置与每次运行记录；设置页负责关窗行为、数据目录与休眠设置。导航只呈现已经可用的页面。

## 必须绘制的工作台状态

线框图要覆盖无任务、正在输入首条指令、启动中、执行中、等待审批、指令排队、停止后排队暂停、完成、失败、中断、待核验、连接中断与重新连接。对每种状态，标出用户能做的操作及其结果。审批卡要展示目标与参数、四种决定及“始终”决定的保存范围；文件写入只有在权限规则要求人工决定时才展示审批。停止当前执行后，排队指令保留并暂停。待核验状态须阻止恢复执行，并给出提交查证结果的入口。

新建任务时，当前只有一名可用员工便直接使用“小文”；多名员工时允许选择。用户能选取单个文件并导入任务资料目录，也能选择原位置文件夹；界面在发送前展示工作空间、材料与文件访问范围。完成或失败后，产物卡保留真实文件路径与状态。运行详情与任务正文显示同一批事件，不能出现彼此矛盾的执行状态。

## 其他页面的关键状态

自动化页面需画出创建时的预授权范围、启用状态、下一次运行、已错过、已跳过、被拒和待核验记录。运行中心需画出事件时间线、回放控制、恢复产生的多次执行尝试及审计报告到原始事件的跳转。员工管理与管理中心需画出授权范围、撤销入口、演示身份提示和审计链校验失败后的只读诊断。设置页需画出关闭窗口、真正退出与运行中任务的提示。

Figma 交付物须标注主要点击目标、折叠关系、空白与错误状态，以及文本较长、路径较长、窄窗口时的信息处理。具体尺寸、字号、色彩和组件形态由 UX Agent 决定。前端实现必须以实际事件和接口数据驱动这些状态。
