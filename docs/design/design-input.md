## 1. 产品一句话与 MVP 用户故事

**桌面端数字员工平台：能派活、能看见它干活、能管住它（审批）、坏了能恢复。**界面采用浅色、简约的 macOS 风格；用户已明确不采用深色主题。

MVP 六个用户故事（设计必须让它们走得通）：
1. 新建任务，给数字员工"小文"派一个真实活（如"整理 inbox 里的文件"）
2. 全程看见它在干什么（读文件、执行命令，实时）
3. 它要写文件时出现审批卡，我批准（或"始终允许"）
4. 任务完成，看到产物文件，点开核对
5. 应用中途被强杀，重开能恢复任务
6. 它干活时我再发一条指令 → 排队 → 干完自动接续

## 2. MVP 屏幕范围

**只有一块主屏：Cowork（工作台）**，外加极简设置与空态。必须承载的功能点：

| # | 功能点 | 说明 |
|---|---|---|
| F1 | 任务列表与新建 | 左侧（或设计认为对的位置）；新建 = 选员工（MVP 只有小文）+ 起名 |
| F2 | 聊天流 | 我的指令、小文的最终回复（流式打字）、过程展示 |
| F3 | 过程展示 | 步骤/工具调用：进行中/完成/失败三种状态；工具参数与结果可查看 |
| F4 | 审批卡 | 高危操作出现；**语义四选项：仅本次允许 / 始终允许 / 拒绝 / 总是拒绝**（呈现方式设计定，但四种决定都要有入口，可收纳如下拉） |
| F5 | 排队指示 | 第二条指令在排队中可见；当前执行正常结束后自动接续；用户停止执行后，未开始的指令暂停，等待用户继续或取消 |
| F6 | 停止与恢复 | 运行中可停止；停止后保留并暂停排队指令；"已中断"任务有恢复入口 |
| F7 | 产物文件卡 | 完成后列出产出文件（名/类型/大小/打开） |
| F8 | 员工身份 | "小文 · 办公助理"+ 工作状态（正在工作/空闲） |
| F9 | 空态 | 无任务时的引导 |
| F10 | 设置（极简） | 关窗即退出开关、数据目录展示 |

## 3. 可用数据与状态（设计可以拿到的"原材料"）

- **任务状态机**：空闲 / 启动中 / 运行中 / 出错；运行中可叠加"等待审批 ×N""等待提问 ×N"
- **输入框三态**：可输入（空闲）/ 可发送但提示将排队（运行中）/ 禁用提示先处理审批
- **排队暂停态**：停止当前执行时，未开始的指令保留且暂停；界面提供继续处理或取消排队指令的入口
- **实时事件流**（SSE，逐条到达）：任务开始/结束/失败、每步开始/完成、每次模型请求（token/耗时）、每次工具调用（参数/结果/状态）、审批请求/决定、中断/恢复——**界面上任何"进度"都来自这些事件**
- **文件芯片可用字段**：文件名、扩展名、大小、状态（生成中/完成/失败）
- **刷新/重连行为**：界面从事件重放自动恢复（设计需考虑"重新连接中"过渡态）

## 4. 硬约束（不可违反）

1. **macOS 桌面应用**（Electron 窗口），按桌面端设计，不做移动假设
2. **中文界面**
3. **事件驱动渲染**：UI 状态是事件流的投影（设计画的状态 = 事件能支撑的状态，不多不少）
4. 审批四选项语义不可缺（见 F4）
5. 组件库基线 **Ant Design 5**（可换，需给理由与成本）
6. 技术栈 React + Vite + TS（设计不受限，但交付物要能被前端实现）
7. 左侧任务列表与整条侧栏均可收起；右侧运行详情可收起，收起后仍可查看当前状态

## 5. 移交给设计的开放问题（此前收集的全部 UI 问题）

空态具体形态；排队指令显示位置；中断任务标记与恢复入口；停止按钮位置与确认方式；失败态视觉；审批四选项的呈现方式；设置页形态。右侧运行详情的内容与展开方式，以及不可用功能的导航处理，以产品 Agent 的页面与流程规格为准。

## 6. 交付物建议

产品 Agent 的页面与流程规格经用户确认 → UX Agent 绘制线框图与 Figma 高保真稿（含颜色、字号、间距、圆角）并标注空态、加载、错误、审批、排队暂停和中断恢复状态 → Frontend Agent 按确认稿实现。设计产出放 `docs/design/`。
