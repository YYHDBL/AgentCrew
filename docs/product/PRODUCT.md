# AgentCrew 产品定义

> 产品负责人维护。本文规定用户、产品边界和页面职责；具体操作见 [USER-FLOWS.md](./USER-FLOWS.md)，单项功能见 [features](../features/)。本文描述目标产品，不代表功能已经实现。

## 用户与使用目的

AgentCrew 服务于一名在 macOS 上处理日常办公事务的人。用户用自然语言交代任务，让本地数字员工读取获准访问的材料，调用文件、文档、表格、HTTP 和定时能力，交付可以打开、检查和继续修改的结果。项目所有者是首位真实用户。招聘方和开发者会查看作品与代码，但不承担产品内的日常工作角色。

用户需要完成的工作不限定为一类示范任务。常见场景包括整理文件、从已有资料制作文档或表格、查询网页后形成交付文件、持续处理同一项工作，以及设置有明确授权范围的定时任务。任务内容由用户决定；产品提供通用的输入、执行、检查和控制方式。

产品同时展示可理解的 Agent 工程能力：执行过程有记录；需要授权的操作能够由人决定；异常退出后能够辨认已经发生的操作并恢复；每次运行可审计、可回放。演示组织用于真实运行角色和权限机制，产品仍由单个本地用户使用。

## 产品边界

产品运行在 macOS 桌面端，采用 Electron 与 React 界面、Python sidecar 和 Python Agent 核心。Agent Harness 由项目自行实现，不依赖 LangGraph 或 litellm 一类框架。模型使用可配置的主模型槽和辅助模型槽，支持 GLM 的 Anthropic Messages 协议与 DeepSeek 等模型的 Chat Completions 协议。用户不编写前端代码。数据和任务在本机管理；定时任务依赖应用运行与电脑可用，不承诺电脑关机后继续执行。不提供多人在线协作服务器。

项目以约一个月的全职开发作为实施约束，同时要成为可以真实自用的求职作品。代码应便于学习和继续开发；权限、记录与恢复机制完整，具体实现保持清楚。项目不承担开源社区运营。

数字员工执行真实工具调用。界面不得把模型文字描述当成工具完成的证据；文件产物、权限决定和运行状态分别来自实际文件、权限记录和事件记录。产品范围包含创建与管理数字员工、能力授权、定时任务、运行回放、审计查询及异常恢复。这些能力对应已有架构设计；各页面的细节以对应 Feature Spec 确定。

## 用户可理解的对象

| 名称 | 用户看到的含义 |
|---|---|
| 工作空间 | 放置数字员工、授权和任务的业务范围；预置组织提供演示工作空间。工作空间也有对应的本地数据目录。 |
| 任务 | 可持续交流的一条工作记录。用户在任务中交代多条指令、查看回复与产物。后端对应一个 conversation。 |
| 指令 | 用户在任务里发送的一次要求。运行中发送的指令按顺序等待。 |
| 执行记录 | 数字员工处理一条指令的过程，包括步骤、工具调用、审批和最终结果。恢复执行会增加一次尝试，历史记录保留。 |
| 数字员工 | 带岗位说明、可用技能、连接器及权限规则的执行者。任务创建时使用其当时的配置快照。 |
| 产物 | 执行真实创建或修改的文件，必须显示路径和当前可用状态。 |

任务对应的工作空间与本地文件访问范围必须让用户看得见。选取外部文件或文件夹只表示提供任务材料；实际读取、修改及联网仍受员工能力、授权规则和审批控制。无法读取的材料应明确提示，不能表现为已经处理。

## 页面与导航

**工作台**是默认入口。左侧放新建任务、最近任务及可用工作空间；任务列表和整条侧栏分别可以收起。中间放当前任务的指令、回复、执行概览、审批、排队和产物，底部保留输入区。右侧是可收起的当前运行详情，显示步骤时间线及选中步骤的工具信息。右侧收起时，当前状态和待处理审批仍在中间或顶部可见。窄窗口优先保证任务内容与输入区可用。

**运行中心**按任务和执行记录查看历史、事件时间线、回放、失败原因与审计报告。**数字员工管理**用于创建或编辑员工、查看技能和已授权范围。**管理中心**用于演示身份、角色、资源授权、连接器和审计链诊断。**自动化**用于创建、查看、停用定时任务及每次运行记录。**设置**管理桌面运行行为和本地数据位置。导航只显示当前实际可用的页面；未实现的功能不占用假入口。

界面使用中文，采用浅色、简约的 macOS 风格。页面信息顺序与状态变化由产品规格决定；尺寸、字体、色彩和组件形态由 UX Agent 在 Figma 中设计。概念图只提供视觉参考。

## 核心操作原则

新建任务直接进入可输入状态。当前只有一名可用员工时使用预置的“小文 · 办公助理”；存在多名可用员工时，用户可以在发送前选择。发送首条指令才创建任务并开始执行。用户可附加本地文件或选择任务文件夹；未选择时使用当前工作空间的数据目录。单个文件导入任务资料目录，原文件保持不变；选择文件夹时在原位置使用该文件夹，界面明确提示其路径和访问范围。界面在执行前显示任务所处工作空间与文件访问范围，工具操作仍经过权限判断。

运行期间，用户能看到当前动作及已经完成的步骤，能展开参数、结果和时间。用户在同一任务中继续发送指令时，系统明确提示该指令将排队，并显示顺序。当前执行正常结束后按顺序启动下一条。用户主动停止当前执行时，尚未开始的指令保留并暂停；用户可以继续处理或取消这些指令。等待审批时先处理审批请求，暂不接收新指令。

权限由工具风险、员工规则和当前调用共同决定。已经授权的范围内操作可以直接执行；未获规则放行且允许人工决定的调用展示审批。审批提供仅本次允许、始终允许、仅本次拒绝、始终拒绝四种决定，持久决定必须显示作用的工具与资源范围。超出员工能力、被明确拒绝或禁止执行的操作应显示实际拒绝原因。预置“小文”在工作空间内的部分文件写入已获授权，因此文件写入并非一律弹审批。

完成时显示最终回复及可打开的产物。失败时保留已完成的步骤与产物，并显示错误详情。应用异常退出后，任务保留历史并标为中断；可确认结果的操作由系统核验，结果不明的外部操作暂停自动重试，等待用户核验。恢复后以新的执行尝试继续，历史审批、文件及步骤可追溯。

定时任务必须显示执行时间、目标任务、数字员工和预授权范围。范围外的工具调用直接拒绝并记录；错过的执行保留“已错过”记录，不补跑；上一次尚未完成时记录“已跳过”。每次触发都有独立运行记录，可从自动化页面返回任务与运行中心。

## 可验收的产品结果

用户能够从空白工作台交代一项自选的办公任务，看到真实执行过程，处理一次确需人工决定的操作，打开真实产物，在同一任务继续指挥，并在异常退出后看到可靠的恢复或待核验状态。另能创建定时任务并检查其授权、触发与运行结果。运行中心可以根据事件记录重建一次运行，不依赖模型编写的事后叙述。每个能力的具体验收动作由 Feature Spec 记录，不要求用户事先发明一个固定的“首个真实任务”。

## 设计与实现的交接

产品文档决定页面职责、状态和操作结果；UX Agent 据此绘制线框图与视觉稿；Frontend Agent 实现界面；后端 Agent 维护接口与事件契约。当前 [接口契约](../contracts/openapi.yaml) 已提供任务材料与文件范围、暂停队列的继续或取消、待核验结果提交、恢复执行及消息分页等操作。员工管理、资源授权、运行中心和自动化等后续功能开始实现前，继续补齐各自接口与事件契约，让前端只展示真实可得到的状态。这些是团队之间的规格工作，无需用户另行选择产品方向。
