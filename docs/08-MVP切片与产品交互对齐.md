# 08 · MVP 切片与产品交互对齐

> 版本：v1.1 ｜ 日期：2026-09-28
> 定位：补齐 PRD/交互层。**产品由用户主导设计**（决策 + Figma），AI 负责把决策整理成交互规格与接口契约，**不做前端设计决策**。
> 开发模式改为：**MVP 切片 → 交互设计 → 接口冻结 → 前后端并行 → 联调 → 真用反馈 → 从增量池拉下一片**（替代"一次对齐完就全做"）。
> **v1.1：用户已提交概念图 `assets/agentcrew-desktop-concept-v1.png`，下列 §3.0 为其定下的基线；未覆盖的点集中在 §3.9。**

## 1. MVP 定义（用户可见的产品，不是机制清单）

**一句话：一个能真实干活的数字员工桌面应用——能派活、能看见它干活、能管住它（审批）、坏了能恢复。**

六个用户故事（= MVP 验收）：
1. 打开应用，创建会话，给预置数字员工"小文"派一个真实任务（整理杂乱文件）
2. 全程看见它在干什么（读文件、执行命令，每一步实时可见）
3. 它要写文件时弹审批卡，我批准（或"总是允许"）
4. 任务完成，看到产物文件卡，点开核对
5. 中途强杀应用，重开后任务可恢复，文件没有重复副作用
6. 它干活时我再发一条指令，会排队，干完自动接续

**MVP 明确不包含**（进增量池）：创建/管理多个员工、记忆系统、运行中心、组织与权限管理页、定时任务、多 Agent、第二供应商、安装包。

**MVP 只有一块屏：Cowork（会话列表 + 聊天 + 过程 + 审批）。** 小文由种子数据预置（无创建流程）。

## 2. 增量需求池（MVP 之后按需拉取，每片走完整循环）

| 片 | 内容（产品语言） | 原里程碑对应 |
|---|---|---|
| P1 员工管理 | 创建/编辑数字员工、soul 查看、已授权清单 | 原 M2 部分 + Studio |
| P2 记忆 | 员工记得住事、soul 成长、记忆管理页 | 原 M1 |
| P3 运行中心 | 任务录像回放、失败归因、审计报告 | 原 M3 部分 |
| P4 组织治理 | 角色、授权矩阵、审计链、演示身份 | 原 M2 部分 |
| P5 定时与通知 | 值夜班、早晨报告、预授权 | 原 M3 部分 |
| P6 分发 | DeepSeek、dmg 安装包 | 原 M4 |
| P7 多员工协作 | fork 子员工、主管派活 | 原 M5 |

顺序可按真实使用反馈调整（这就是"不断往上加需求"）。

## 3. Cowork 屏交互点决策清单（**本轮待用户拍板**）

> 用法：逐条回"同意默认"或写你的答案；也可以先在 Figma 画，画完对照本清单勾。**全部落定后我出《交互规格 v1》并冻结接口。**

### 3.0 概念图 v1 定下的基线（用户设计，2026-09-28）

依据 `assets/agentcrew-desktop-concept-v1.png`，以下直接取代 §A–H 中对应条目的默认值：

| 基线项 | 内容 |
|---|---|
| 布局 | **三栏**：左侧深色导航（新建任务/工作空间/数字员工/自动化/运行记录 + 最近任务列表 + 用户区）；中间聊天主区；**右侧"运行详情"面板** |
| 视觉 | 深色主题，Linear/Cursor 风；青绿主色；状态色绿（完成）/黄（等待审批）；大圆角卡片 |
| 任务语言 | UI 全程用"**任务**"而非"会话"（新建任务、最近任务）——数据模型映射：**一个"任务"线程 = 一个会话**，后续指令在该任务内排队（与 D5 一致） |
| 过程展示 | 结构化**步骤卡**（步骤 1/2、完成✓/进行中 spinner）+ **文件芯片**（文件名+类型彩标+状态+大小，如"周报.docx · 生成完成 · 2.4MB"） |
| 审批卡 | 聊天内联卡：操作描述 + 文件行（路径/操作类型/大小）+ **三按钮：仅本次允许（主）/ 始终允许 / 拒绝** |
| 运行详情面板 | 四卡：任务信息 / 执行步骤时间线 / 文件范围（路径/操作/大小/权限）/ **审计记录（逐条带时间戳）** |
| 输入区 | 任务下发器风格：多行输入 + 附件按钮 + **数字员工选择器 + 联网搜索开关 + 工具选择**（后两者 MVP 处理见 §3.9-8） |
| 顶部状态 | "小文 · 办公助理"+ 绿点"正在工作" |

**范围影响（须知）**：右栏"运行详情"意味着**迷你运行中心进入 MVP**（步骤时间线 + 审计记录）——实现上是同一事件流的第二个视图，成本可控，接受；原增量池 P3 剩"跨任务列表 / Replay 播放器 / 审计 Agent 报告"。

### 3.9 概念图未覆盖、仍待用户拍板的点

1. 空态：没有任何任务时主屏显示什么（引导卡？）
2. 排队指令的可见位置（概念图未画；建议：输入框上方"排队中 ×N"小条）
3. 中断任务：过程卡"已中断"标记 + 恢复按钮的位置
4. 停止按钮：位置（顶部标题栏右侧？）与是否需确认（建议：直接停）
5. 任务失败态：红色卡 + 错误一句话（视觉待 Figma）
6. 设置页：MVP 范围（建议：关窗即退出开关 + 数据目录展示）
7. **审批第四选项"总是拒绝"的入口**：概念图只有三按钮，与 docs 04 的四选项契约有出入——建议：拒绝按钮带下拉（点=拒绝一次，下拉含"总是拒绝"），契约不变 UI 简洁
8. 输入区"联网搜索 / 工具"选择器：MVP 无对应后端能力——建议 MVP 隐藏或置灰"即将上线"
9. 左侧导航的未来入口（工作空间/数字员工/自动化/运行记录）：MVP 置灰 + "即将上线"角标

### A 布局与导航（已被 §3.0 取代大半，保留备查）
- **A1** 布局：左侧会话列表 + 右侧主聊天区？（默认：是）
- **A2** 会话列表项内容：员工头像 + 会话名 + 最近指令摘要 + 状态点（运行中转圈/空闲）？（默认：是）
- **A3** 无会话时空态：中央大按钮"新建会话"+ 一句话引导？（默认：是）
- **A4** 顶部栏：当前员工名 + 模型名小字 + 会话状态？（默认：是，MVP 不放别的）

### B 会话管理
- **B1** 新建流程：点"+"→ 弹窗选员工（MVP 只有小文）→ 自动起会话名（可改）？（默认：是）
- **B2** 会话删除：右键/菜单删除 + 确认弹窗？归档 MVP 不做？（默认：是）

### C 派活与输入
- **C1** 输入框：多行 + 发送按钮；Enter 发送、Shift+Enter 换行？（默认：是）
- **C2** 输入框三种状态：空闲可输入；运行中显示"发送后将排队"仍可发；有审批挂起时禁用并提示"先处理审批"？（默认：是）
- **C3** 排队可见性：输入框上方一条"排队中：×2"小条，点开看内容？（默认：是）
- **C4** 停止按钮：任务运行时出现"停止"，点了直接停（无确认弹窗，低风险）？（默认：是）

### D 任务过程展示（最需要设计的一块）
- **D1** 过程卡粒度：每个模型回合一张卡，卡内列出该回合的工具调用行？（备选：每个工具一张卡）（默认：回合卡）
- **D2** 工具调用行：图标 + 工具名 + 参数摘要 + 状态（转圈/✓/✗），点击展开参数与结果全文？（默认：是）
- **D3** 模型的思考/中间文本：灰色折叠块默认收起，可展开？（默认：折叠显示）
- **D4** 进行中指示：过程卡顶部当前动作描述 + spinner？（默认：是）

### E 审批交互（核心）
- **E1** 审批卡形态：聊天流内联卡片（不是阻塞全屏弹窗）？（默认：内联卡片）
- **E2** 卡片内容：操作描述 + 关键参数（路径/命令高亮）+ 风险级别徽标 + 四按钮（允许一次/总是允许/拒绝一次/总是拒绝）？（默认：是）
- **E3** 等待审批的可见性：卡片呼吸灯 + 顶部黄条"等待你的批准"？（默认：是）
- **E4** "总是允许"的范围提示：按钮旁小字注明将记录的范围（如"工作区内写文件"）？（默认：是）

### F 完成与产物
- **F1** 完成态：最终回复 + 产物文件卡（文件名 + 大小 + "打开"按钮，系统默认应用打开）？（默认：是）
- **F2** 任务摘要条：完成后卡片底部一行（耗时/步骤数/token）？（默认：是）

### G 恢复与错误
- **G1** 中断任务：过程卡标灰"已中断" + 恢复按钮？（默认：是）
- **G2** 后端重连：全局 toast"连接已恢复，正在同步事件"？（默认：是）
- **G3** 任务失败：红色卡 + 错误一句话 + 无自动重试（重新派活即可）？（默认：是）

### H 设置（MVP 极简）
- **H1** 设置页只有两项：关窗即退出（开关，默认关）、数据目录展示？（默认：是）

## 4. 工作法

1. 用户：回答 §3 清单（或 Figma 画完对照勾选）→ Figma 出 MVP 屏视觉稿
2. AI：据答案 + Figma 产出《09-交互规格》（每个操作的触发、响应、状态变化、边界态）→ 校准 API 面 → 重写前端任务卡（原 07 的 C11 作废待重写；C10 的壳与监管部分不受影响）
3. 后端：07 的 C1–C9 是引擎层，不依赖产品图，可先行（等用户点头开工）
4. 联调 → MVP 真用 → 反馈 → 从 §2 增量池拉下一片（重复循环）
