# M3 实施与真实验收计划

目标：按 M3-01 至 M3-15 顺序完成后端、桌面前端、回归及真实自动验收。范围与逐卡文件清单使用 [M3 实施卡](../tasks/M3-cards.md)，时间和跨层边界使用 [ADR-013](../decisions/ADR-013-automation-and-trace.md)。本次会话直接持续实施，各卡完成后提交并推送主仓库。

架构：core 保存调度计算、权限交集及报告判定，server 保存 SQLite 迁移、串行事务、真实 Harness 派发、辅助作业和生命周期。React 读取生成类型的真实 HTTP/SSE，Electron 使用现有窄 preload、托盘与 sidecar。复用 M1/M2 服务和权限边界。

每张卡先核查当前文件及参考源码，添加能够发现该功能缺失的真实检查或纯函数参数化检查，运行并确认失败归属，再实施完整卡片并重复针对性检查直到通过。每卡记录 SQL、请求、任务、尝试、发生、作业、水位、审计及实际文件结果，报告和脱敏证据分别进入约定目录。运行材料、凭据和中间输出使用 Git 忽略的 data/m3-intermediate 及 desktop/.artifacts，pytest 指定相同范围的 basetemp，禁止使用 /tmp。

M3-01 核对契约及操作归属；M3-02 完成只读运行查询和指标；M3-03 完成计划存储和 API；M3-04 完成真实调度；M3-05 接入无人值守 Harness；M3-06 完成重试及重启对账；M3-07 完成员工持久提案及人工批准；M3-08 完成 aux 轨迹审查；M3-09 完成技能固化；M3-10 核对 HTTP 和生成类型；M3-11 至 M3-14 依次完成运行中心、员工及管理中心、自动化、通知和生命周期；M3-15 完成七项计分、四屏和全部回归。

最终在 backend 执行 uv sync、uv run pytest -q 和 OpenAPI 检查，在 desktop 执行 check:api、typecheck、build 及 m3-acceptance.mjs。每卡指定命令仍逐项执行。真实电源事件未发生时保存验收缺口，模型没有报告或技能提案时保存实际结果；需要有效提案的固化项目必须有真实版本及复用证据才能通过。人工核验及阶段收口由所有者确认。
