## 实现范围

C11 对应 FE01 的接口核对、FE02 的输入交互、FE03 的鉴权 HTTP/SSE、FE04 的会话与材料、FE05 的聊天与步骤、FE06 的审批和提问、FE07 的队列以及 FE10 的刷新重连范围。使用现有 React state 和 Ant Design，新增 `@microsoft/fetch-event-source`；真实 Electron 验收使用 `playwright-core`，不下载浏览器。

先读取 state 得到 `at_global_seq`，通过真实会话 SSE 从零读取截至该水位的历史，恢复聊天、步骤、工具、审批、提问和材料导入结果，再从水位排他续播。历史读取与实时订阅均使用指定 SSE 库。实时帧按 `global_seq` 去重，触发串行合并的 state 查询更新合法动作。resync 重新执行完整恢复；shutdown 保存连续游标；连接失败按 1、2、4、8、16、30 秒退避，重新通过 preload 取得当前端口和 token。切换会话时取消请求和订阅。

当前 C8 没有向会话 SSE 发送文本 delta，使用 `llm.request_done.text` 全文逐字呈现新回复，尊重减少动态效果偏好；恢复的历史回复立即显示全文。用户消息从 run.queued 和 queue.item_enqueued 恢复，通过 queue_item_id 避免队列出队后重复显示。审批与提问由事件出现和结束，任务终态关闭过期操作。输入和队列按钮依据 state 的能力字段，服务端错误直接显示。

原生材料选择通过新增的 preload 窄接口完成；文件和文件夹路径提交给 POST conversations，逐文件导入结果展示在运行详情。开发启动默认读取工作树 backend/data，指定 Electron user-data-dir 的验收实例以及安装应用使用各自应用数据目录。

## 契约核对

公共 OpenAPI 声明 messages 查询，但当前服务未注册该接口；state 只含 FSM 与队列。现有会话流可以恢复全部历史，包含无 task_run_id 的队列事件，因此本卡使用有水位边界的会话历史重放。建议后端明确完整快照或会话历史分页及其水位，避免长期会话必须读取全部历史。

事件 payload 当前详细字段集中在后端 projections.py，公共 events.md 缺少完整 schema。实际队列条目字段为 id，审批事件使用 tool_call_id，工具事件使用 call_id。建议后端维护者将这些字段补入公共契约。

当前模型 delta 未公开为会话流事件；本卡遵循 D2，使用全文逐字呈现，不要求后端持久化 delta。C9 的恢复执行与核验界面不在本卡范围。
