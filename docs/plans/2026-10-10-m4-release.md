# AgentCrew M4 发布实施计划

> 实施时使用 executing-plans 技能逐卡执行；详细范围、文件和验收条件以 [M4 任务卡](../tasks/M4-cards.md) 为准。

**Goal:** 交付可独立安装运行的 macOS arm64 应用，完成配置、数据保护、产品打磨、真实演示和双供应商核验，准备可审核的正式发布产物。

**Architecture:** Electron 保持窗口、原生能力与 sidecar 监管；生产按资源绝对路径启动 PyInstaller 可执行文件，通过本地带 token 的 HTTP/SSE 使用后端。模型编码资源随包提供，可写数据进入稳定 userData，所有操作继续遵守已有审批、Grant、Seatbelt 和审计契约。

**Tech Stack:** Electron、React、TypeScript、Ant Design、electron-vite、electron-builder、Python、PyInstaller、SQLite、现有模型适配、Playwright，以及现有依赖锁文件。

## 实施顺序

按 M4-01 至 M4-06 完成版本基准、自包含后端、生产启动、首次设置、DMG 和数据保护。随后完成 M4-07 的页面统一、M4-08 的真实场景，以及 M4-09 的供应商与官方计数资源。最终对包含全部资源的包执行 M4-10 签名/公证，完成 M4-11 文档，再由 M4-12 对同一实际安装包执行交付核查。

每张卡先检查真实现状和调用路径，补充能重现缺陷的实际检查，再实施产品变更并运行适用测试；保存脱敏证据与单卡报告后提交该卡归属的文件。构建依赖在对应卡片锁定，生成内容在被忽略的目录保存。用户要求仅规划任务卡，本次不会启动产品实施、恢复 M3 验收或发布上传。

## 发布检查范围

安装包必须在独立环境从 Finder 启动，完成真实配置和文件任务、审批、回放、授权拒绝、退出与数据恢复。开发机的构建通过不能替代安装包验证。正式包签名、公证、资源许可、密钥扫描和 SHA-256 均对应最终版本。

M3 验收保持暂停；M4 检查单独记录结果，阶段报告不将未执行的 M3 全量回归或未取得的系统通知/电源证据宣称通过。实际发布上传等待所有者对完整产物的明确授权。
