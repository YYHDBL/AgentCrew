# M3 验收交付实施计划

**目标：** 完成桌面错误反馈、回归脚本适配、M3-14 证据报告和 M3-15 材料与贯穿验收载体，按实际运行结果记录阶段交付状态。

**结构：** 产品继续使用现有 HTTP、事件订阅、限定 preload 和统一退出流程。回归脚本通过真实页面导航与退出确认完成操作，验收材料与证据存储使用独立数据目录。平台事件依据真实运行记录判断。

**技术：** Electron、React、TypeScript、Playwright、Python 标准库、SQLite，以及当前配置的真实 main/aux 模型。

## 实施范围

前端错误处理修改 `desktop/src/renderer/src/DesktopSettings.tsx` 和 `Notifications.tsx`。设置保存失败显示实际错误，通知读取在正常轮询周期中处理失败并继续核查。身份变更和请求取消保持原来的权限边界。

回归脚本修改 `desktop/tests/` 下实际受导航与退出流程影响的文件。新增共享导航与退出辅助函数，保持业务断言和真实调用不变；旧脚本通过设置分页与记忆菜单进入当前页面，退出流程点击真实确认按钮并核查进程结束。

验收材料新增 `scripts/seed/m3_automation_data.py`，产生真实文件与可核对的清单。M3-15 新增 `desktop/tests/m3-acceptance.mjs`，覆盖定时计划、授权与审批、报告定位、技能发布复用和四屏操作，并保存请求、事件、SQL 与文件证据。

验收报告新增 `docs/acceptance/M3-14.md` 和 `docs/acceptance/M3.md`，同步 `docs/tasks/M3-cards.md` 中的状态。每项分别记录通过、失败、未验证及来源，系统通知真实点击与真实电源事件依据实际证据登记。

## 执行与检查

先对各问题补充真实失败验证，再修复对应位置。前端修改后运行类型检查、构建、设置与通知检查；回归脚本完成适配后串行运行 M1、M2 和 M3 的相关真实桌面检查。M3-15 按正式七项要求检查，使用同一流程中的任务、计划、报告、技能版本与授权记录核对四屏交互。

桌面执行 `npm run check:api`、`npm run typecheck`、`npm run build` 和适用的真实脚本。后端执行 OpenAPI 检查与全量 pytest，真实模型配置来源为现有本地配置，pytest 使用显式独立 basetemp。全部中间结果保存到已忽略的 `desktop/.artifacts/` 下，公开报告排除密钥和身份令牌。

最终核查文件改动、测试退出码、事件水位、文件结果和后台进程清理。阶段状态与报告保持一致，证据不足的项目保留未验证。
